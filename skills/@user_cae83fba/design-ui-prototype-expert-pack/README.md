# 设计 UI 原型专家包

把 PRD、需求说明或产品想法转成可评审 UI 原型、设计规范、设计系统与前端交接清单，并对已有原型做证据化质量评审。

## 主要能力

- **需求转产品结构**：拆解目标、非目标、用户角色、主路径与异常路径。
- **流程转线框图**：把流程落成低保真页面规格、信息层级与交互说明。
- **线框转 UI 规格**：输出参数化视觉规则，覆盖色彩、字体、间距、组件样式与断点。
- **UI 转设计系统**：整理设计 token、组件状态表与复用边界。
- **UI 转前端交接**：准备组件拆分、状态机、接口字段、埋点建议与验收用例。
- **可评审 HTML 原型**：输出单文件原型，含内嵌样式与脚本，可直接点击演示。
- **原型评审与走查**：对已有原型按 P0/P1/P2 分级并给 100 分制评分，逐条附证据。
- **无障碍检查**：对比度、焦点可见、键盘可达、状态冗余表达四项作为硬门槛。
- **响应式验收**：窄屏、笔记本、宽屏三档断点下的布局变化检查。
- **交互动效基线**：给时序区间与反馈要求，避免只写风格形容词。
- **输入分流**：先判定输入类型（完整 PRD、零散想法、仅截图、超范围），再决定补问内容。
- **降级交付**：信息不足时按「已知事实 / 合理假设 / 待确认事项」三类分开输出，不停止推进。

## 安全边界

1. 不承诺生产级前端工程交付。交付物为评审级原型、设计说明与交接材料。
2. 不替代真实用户研究、可用性测试、品牌 VI 设计与研发排期。
3. 未获用户授权不删除、不覆盖原项目文件。
4. 不把示例、客户资料、本机路径与内部项目名写入对外发布包。
5. 缺少原始需求时不声称需求覆盖已通过，只列待核对项。
6. 不照搬竞品设计，参照时只提取通用结构与规则。
7. 不把待确认项当作已确认事实推进，假设与事实分开记录。

## 使用示例

### 应触发的请求

| 用户请求 | 预期行为 |
|---|---|
| 把这份 PRD 转成可评审 UI 原型 | 走快速或标准档，输出页面清单、线框规格、UI 参数与自检结论 |
| 根据这个业务流程设计后台页面和交互说明 | 走标准档，输出流程状态、页面区块、交互说明与交接清单 |
| 把这个线框图升级成高保真 UI 设计规范 | 走标准档，输出参数化视觉规则、组件样式与响应式规则 |
| 从这些页面沉淀一套设计系统 | 输出设计 token 表、组件状态表与复用规则 |
| 检查这个 HTML 原型能否用于研发评审 | 读取原型文件后按 P0/P1/P2 评审并给评分；未读取时只列待核对项 |

### 不应触发的请求

| 用户请求 | 原因与处理 |
|---|---|
| 帮我做一套品牌 VI 和 Logo | 属品牌与平面设计范畴，说明超出范围并给出替代方向 |
| 帮我重构这个 React 工程的代码 | 交付物定位为评审级原型，不含生产级代码重构 |
| 帮我们做用户访谈和可用性测试 | 本技能不产生一手用户数据，属用户研究范畴 |

### 写作方式

- 用户可见说明、指南、案例、模板与 QA 规则使用中文；文件名、字段名、英文 slug 与通用技术术语保留原文。
- 段落不超过 5 行，能用表格的不写成段落。
- UI 与交互规则用数值或 token 名表达，不用风格形容词。
- 每条结论标明来源；无来源的判断写入待确认事项。

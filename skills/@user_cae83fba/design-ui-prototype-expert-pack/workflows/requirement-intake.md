# 需求接收工作流

覆盖专家 01 需求到产品结构。用于收到用户需求后判断直接推进、先追问，还是降级交付。门禁细则见 `references/clarification-gate.md`。

## 输入契约

| 字段 | 类型 | 必需 | 缺失时处理 |
|---|---|---|---|
| userInput | 文本 | 是 | 阻断，E-INPUT-01 |
| outputPurpose | 枚举：评审 / 开发交接 / 演示 | 是 | 阻断，E-INPUT-02 |
| targetUsers | 文本或列表 | 是 | 阻断，E-INPUT-03 |
| businessGoal | 文本 | 否 | 追问一次，仍缺失标为假设并阻断进入 02 |
| prd | 文本或文件 | 否 | 带假设推进，标注影响范围 |
| screenshots | 图片文件 | 否 | 不可读时阻断，E-INPUT-04 |
| existingPages | 文本或文件 | 否 | 不阻断，按全新设计处理 |
| industryContext | 文本 | 否 | 缺省不做行业声明，03 阶段需重问 |
| constraints | 文本 | 否 | 列入 openQuestions |

## 门禁

进入主交付前逐条判定，命中任一条即阻断。门禁细则与 E 码见 `references/clarification-gate.md`。

| 门禁 | 判定标准 | 命中后动作 |
|---|---|---|
| M1 目标可复述 | 一句话能说清为谁解决什么问题 | 走 Q1 追问 |
| M2 用户明确 | 目标角色可指认，不用泛称 | 走 Q1 追问 |
| M3 用途明确 | 评审、交接、演示三者之一 | 走 Q2 追问 |
| M4 材料可读 | 文件、截图、链接均已成功读取 | 要求补充材料 |
| M5 范围未越界 | 未要求生产级代码 | 说明边界并降级 |
| M6 素材合规 | 未要求照搬竞品 | 说明合规风险并降级 |

MRC 门禁指 M1 至 M3 的组合，三项全过才允许输出页面清单。任一未过时不进入主交付，转第 3 步。

## 执行步骤

1. **输入分流**。判定输入属于四类中的哪一类：模糊想法、残缺 PRD、纯截图、越界请求。四类走不同处理路径。
2. **门禁判定**。执行 M1 至 M6，命中项转第 3 步，未命中直接进第 4 步。
3. **选项化提问**。按追问规则提问，一次不超过 5 个，每题给 2 至 3 个候选。
4. **产出产品结构**。按目标与非目标、用户与场景、页面清单、流程、风险五段输出，页面清单每项须写存在理由。
5. **标注假设与风险**。分区标注已知事实、合理假设、待确认事项，每条假设写来源与影响范围。
6. **自检交付**。对照 `data/schemas/page-inventory.schema.json` 校验结构，确认非目标不少于 2 条、主路径可复述。

### 输入分流对照

| 输入类型 | 特征 | 处理路径 |
|---|---|---|
| 模糊想法 | 一句话，无角色无范围 | 先走 M1 至 M3，再产出目标与非目标草案 |
| 残缺 PRD | 有文档但缺状态、权限或规则 | 抽取已知部分，缺口进 openQuestions 并标 blocking |
| 纯截图 | 只有图片 | 先问 Q5 明确意图，再判断能否读出页面结构 |
| 越界请求 | 要求生产级代码或照搬竞品 | 说明能力边界，输出降级清单 |

## 输出契约

| 字段 | 类型 | 校验规则 | 落盘位置 |
|---|---|---|---|
| productGoal | 字符串 | 一句话可复述 | 需求确认表 `goal` |
| nonGoals | 数组 | 至少 2 条 | `nonGoals` |
| users | 数组 | 每项含 role、task | `users` |
| pages | 数组 | 每项 reason 不少于 8 字 | `pages[]` |
| mainPath | 数组 | 至少 2 步 | `mainPath` |
| assumptions | 数组 | 每条含 source 与 impact | `assumptions` |
| openQuestions | 数组 | blocking 为 true 的阻断下游 | `openQuestions` |
| risks | 数组 | 至少 1 条 | `risks` |

落盘文件名 `01-requirement-structure.md`。字段定义见 `data/schemas/delivery-contract.schema.json` 的 `requirementConfirmation` 段。

## 追问规则

| 编号 | 触发门禁 | 问法 | 选项 |
|---|---|---|---|
| Q1 | M1 或 M2 未过 | 这份结构主要给谁看 | 运营执行层 / 业务管理者 / 外部客户 |
| Q2 | M3 未过 | 产物准备用在哪一步 | 内部评审 / 研发交接 / 对外演示 |
| Q3 | 页面清单易膨胀 | 本次不解决哪些范围 | 暂不做移动端 / 暂不做数据导出 / 暂不做权限细分 |
| Q4 | 业务规则影响主路径 | 关键动作的规则由谁定 | 产品已定 / 需业务方确认 / 暂按常见规则假设 |
| Q5 | M4 命中且为纯截图 | 这批截图用来做什么 | 复盘问题 / 提炼设计系统 / 优化现有页面 |

## 降级出口

MRC 门禁未全过时交付五项，不进入页面清单主交付：当前可确认的信息并标注来源；信息缺口清单；需要用户补充的材料清单；可继续推进的最低版本，例如仅目标与非目标加主路径草案；下一步建议，说明补齐后回到第 1 步。降级状态下不得输出完整页面清单并暗示可直接进入 02。

## 反模式

- 直接开始画页面，跳过 M1 至 M3。
- 追问超过 5 个，把用户拖入长问卷。
- 残缺 PRD 的空白处按行业惯例自行填满，不标来源。
- 越界请求照单全收，产出看起来完整但无法落地的交付。
- 把「需要更详细的需求」当作追问，问题本身不可回答。

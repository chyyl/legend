# 全链路编排工作流

覆盖专家 01 至 06。用于多阶段连续交付时编排执行顺序、裁剪深度、传递上下文与处理中断。

## 输入契约

| 字段 | 类型 | 必需 | 缺失时处理 |
|---|---|---|---|
| userInput | 文本 | 是 | 阻断，E-INPUT-01 |
| targetStages | 数组，取值 01 至 06 | 否 | 缺省按输入类型自动路由 |
| depth | 枚举：全量 / 标准 / 精简 | 否 | 缺省按标准 |
| outputPurpose | 枚举 | 是 | 阻断，E-INPUT-02 |
| targetUsers | 文本或列表 | 是 | 阻断，E-INPUT-03 |
| pageBudget | 整数 | 否 | 缺省不设上限，页面数由目标推导 |
| existingArtifacts | 数组 | 否 | 缺省从 01 起步 |

## 门禁

| 门禁 | 判定标准 | 命中后动作 |
|---|---|---|
| F1 起点合法 | 起始阶段所需输入齐备 | 缺什么补什么，或回退到更早阶段 |
| F2 阶段顺序 | 不跳过必经阶段 | 说明跳过的后果，建议补做 |
| F3 深度可支撑 | 目标阶段在当前深度下有足够信息 | 提升深度或补材料 |
| F4 上下文完整 | 上游产物字段齐备 | 缺字段回上游补，不在本段臆造 |
| F5 交付物可验收 | 每段输出可通过对应 schema 校验 | 补齐字段后再进下一段 |

## 执行步骤

1. **路由起点**。按 `playbooks/expert-router.md` 的决策表判定起始阶段。用户已有产物时从对应阶段起步。
2. **选择深度**。按三档裁剪，见下表。
3. **逐段执行**。每段执行前读对应 workflow 文件，输出后按 schema 校验。
4. **传递上下文**。把上游结构化产物作为下游输入，字段缺口登记为 openQuestions。
5. **阶段确认**。每段结束判断是否进入下一段，未达质量门槛则回退或降级。
6. **收口交付**。汇总六段产物，给整体结论、遗留风险与建议。

### 三档深度裁剪

| 档位 | 适用 | 保留内容 | 省略内容 |
|---|---|---|---|
| 精简 | 需求已明确，只做评审准备 | 页面清单主线、主路径、关键状态 | 分支路径、部分异常、埋点 |
| 标准 | 常规评审与交接 | 六段主干，每段关键字段齐备 | 行业深度反模式全量对照 |
| 全量 | 复杂或多角色项目 | 全部字段、全部状态、行业反模式逐条 | 不省略 |

### 阶段间上下文传递

| 上游 | 传递字段 | 下游 |
|---|---|---|
| 01 | pages、mainPath、users、risks | 02 |
| 02 | blocks、primaryActions、coveredStates、jumpTargets | 03 |
| 03 | fontScale、colorSemantics、spacingTokens、antiPatternChecklist | 04 与 05 |
| 04 | primitiveTokens、semanticTokens、components | 05 |
| 05 | components、fields、eventBehaviors、breakpoints | 06 |

### 中断恢复

| 中断位置 | 恢复方式 |
|---|---|
| 01 门禁未过 | 补齐必需输入后从第 1 步重跑 |
| 02 之后 | 读取已落盘的 01 产物，只重跑 02 及下游 |
| 03 之后 | 保留 uiSpec，从 04 继续 |
| 05 之后 | 保留交接清单，只执行 06 评审 |
| 06 之后 | 按问题严重度回退对应阶段，不整体重做 |

## 输出契约

| 字段 | 类型 | 校验规则 | 落盘位置 |
|---|---|---|---|
| route | 数组 | 实际执行的阶段序列 | 执行记录 `route` |
| depth | 枚举 | 三档之一 | 执行记录 `depth` |
| artifacts | 数组 | 每段产物含 stage 与落盘文件名 | 执行记录 `artifacts` |
| openQuestions | 数组 | 跨段未解决问题汇总 | 执行记录 `openQuestions` |
| verdict | 枚举 | 完成 / 部分完成 / 降级交付 | 执行记录 `verdict` |
| nextActions | 数组 | 下一步建议，含责任方 | 执行记录 `nextActions` |

落盘文件名 `00-full-chain-record.md`。各段字段定义见 `data/schemas/delivery-contract.schema.json`。

## 追问规则

只在跨段边界追问，单段问题交由该段 workflow 处理。

| 编号 | 触发条件 | 问法 | 选项 |
|---|---|---|---|
| Q1 | 起点有多个候选 | 从已有产物中哪一份开始 | 最新一份 / 完整度最高 / 指定某段 |
| Q2 | 深度未定 | 本次需要多深的产物 | 精简 / 标准 / 全量 |
| Q3 | 上游产物有缺口 | 是回上游补齐还是本段假设 | 回上游补 / 本段假设并标注 / 暂停 |
| Q4 | 跨段规则冲突 | 两段结论矛盾时以哪段为准 | 以最新段为准 / 以用户确认为准 / 暂停并追问 |
| Q5 | 中断后恢复点不清 | 从哪一段继续 | 从中断段 / 从最近未通过段 / 从头复核 |

## 降级出口

F1 或 F4 命中时，交付四项：已完成阶段的产物清单与落盘路径；阻塞点与缺失字段；下游不可执行的原因；恢复所需材料清单。不允许在缺上游字段的情况下推进下游并声称完成。

## 反模式

- 六段全跑但每段都跳过质量门槛，产出六份半成品。
- 深度选择与项目复杂度不匹配，标准深度用于全量场景。
- 上游缺字段时在下游臆造，字段一路失真。
- 中断后从头重跑，浪费时间且覆盖已有正确结论。
- 把编排当成流水线，不做阶段确认直接串行执行。

# 线框图到 UI 规格专家

通用追问触发条件、通用信息缺失处理与通用输出契约见 `playbooks/expert-router.md`，本文件只写本段特有内容。

## 1 阶段目标

把线框图转成可执行 UI 规格，明确字体、颜色、间距、组件和可读性标准。执行流程见 `workflows/wireframe-to-ui.md` 第 3 至 5 步。

## 2 职能坐标

| 项 | 内容 |
|---|---|
| 阶段序 | 3/6 |
| 主职能 | 设计 |
| 前置 | 02 的线框规格，含区块顺序与状态覆盖 |
| 可跳过 | 否，但用户已有明确 UI 稿时可只做规范反推与补齐 |
| 下游 | 04 设计系统专家，或 05 前端交接专家 |
| 本段不做 | 组件库搭建、代码实现、token 语义化沉淀 |

## 3 输入契约

| 字段 | 类型 | 必需 | 缺失时处理 |
|---|---|---|---|
| wireframeSpec | 文本或图片 | 是 | 阻断，E-INPUT-07，需先执行 02 或提供页面说明 |
| pages | 数组 | 是 | 阻断，E-INPUT-05 |
| primaryActions | 数组 | 是 | 阻断，E-INPUT-08，无主操作无法定义视觉焦点 |
| industryContext | 文本 | 是 | 追问一次，缺省时不写行业声明并阻断进入 04 |
| brandAssets | 文件 | 否 | 不阻断，缺省用中性色系并标注可替换 |
| density | 枚举：紧凑 / 标准 / 宽松 | 否 | 缺省按标准 |
| targetDevices | 数组 | 否 | 缺省按移动端、笔记本、桌面宽屏三档 |
| accessibilityTarget | 文本 | 否 | 缺省按 WCAG AA |

阻断规则：`wireframeSpec` 与 `primaryActions` 缺失时不输出视觉规则，只交付需补齐项。错误码见 `references/error-codes.md`，本条对应 E-INPUT-07、E-INPUT-08。

## 4 输出契约

| 字段 | 类型 | 校验规则 | 落盘位置 |
|---|---|---|---|
| fontScale | 数组 | 至少 5 级，每级含 size、weight、lineHeight、usage | UI 规格 `fontScale` |
| spacingTokens | 数组 | 至少 6 个，命名成 token | UI 规格 `spacingTokens` |
| colorSemantics | 数组 | 每项含 token、usage、forbiddenUsage | UI 规格 `colorSemantics` |
| contrastChecks | 数组 | 每项含 pair、ratio、threshold、pass | UI 规格 `contrastChecks` |
| componentStyles | 数组 | 每项含组件名与视觉规则 | UI 规格 `componentStyles` |
| stateFeedback | 数组 | 覆盖默认、悬停、聚焦、禁用、加载、错误 | UI 规格 `stateFeedback` |
| breakpoints | 数组 | 至少 3 档，含 range 与 layoutChange | UI 规格 `breakpoints` |
| motionSpec | 对象 | 含 durationRange、easing、reduceMotionFallback | UI 规格 `motionSpec` |
| touchTarget | 对象 | 移动端可点击区域不小于 44x44 | UI 规格 `touchTarget` |
| antiPatternChecklist | 数组 | 逐条对照行业反模式给出结论 | UI 规格 `antiPatternChecklist` |

结构校验用 `data/schemas/delivery-contract.schema.json` 的 `designTokens` 段做 token 命名预检。落盘文件名 `03-ui-spec.md`。

## 5 标准输出

| 项目 | 规则 | 理由 | 注意事项 |
|---|---|---|---|
| 字体层级 | 页面标题 24/700、区块标题 16/600、正文 14/400、辅助 12/400、表格内容 13/400 | 五级覆盖页面全部文本层级 | 每级须写使用场景，不只给字号 |
| 颜色语义 | 主色用于主操作，错误色用于失败提示，中性色用于背景与分隔 | 颜色承担语义而非装饰 | 错误与成功不得只靠颜色区分 |
| 间距规则 | 4/8/12/16/24/32 六档 token | 统一间距避免随手取值 | 区块间距不小于 24 |
| 组件样式 | 按钮高度 32/40 两档，输入框 36，边框 1px | 支撑后台密集操作 | 禁用态降不透明度不用降色 |
| 状态反馈 | 默认、悬停、聚焦、禁用、加载、错误、成功 | 覆盖主路径全部可观察状态 | 聚焦态须有可见轮廓 |

## 6 专业判断标准

- 不接受只写高级、现代、简洁这类形容词。
- 视觉决策必须服务任务效率与可读性。
- 字号、颜色、间距、组件状态必须可落地。
- 压缩预览状态下，标题、关键指标与按钮仍需可读。
- 必须给出参数化建议，至少覆盖字体、间距、颜色语义、状态反馈与关键断点。
- 行业反模式要逐条对照给出结论，不写「已注意行业规范」。

### 本段量化锚点

- 字体层级不少于 5 级，缺一级即视为层级不足。
- 间距 token 不少于 6 个，缺省时按 8/12/16/24 补并标注可调整。
- 对比度可复算：普通文本不低于 4.5:1，关键控件不低于 3:1，每项给出比值与阈值。
- 行业反模式逐条对照无踩中，命中项须给出调整后的取值。

参数缺省值（标注「默认值，可调整」）：正文 14px，区块标题 16px，页面标题 24px；常用间距 8/12/16/24；关键文本对比度按不低于 4.5:1；交互动效时长按 150 至 250ms；断点按移动端、笔记本、桌面三档。

## 7 追问规则

| 编号 | 触发条件 | 问法 | 选项 |
|---|---|---|---|
| Q1 | industryContext 缺失 | 这份 UI 服务哪个行业 | 金融 / 医疗 / 政务 / 通用工具 |
| Q2 | 密度未定 | 信息密度偏好 | 紧凑（数据密集）/ 标准 / 宽松（面向消费者） |
| Q3 | 品牌资产缺失 | 是否有既有品牌色 | 有品牌色 / 用中性色 / 暂不确定 |
| Q4 | 断点范围不清 | 需要覆盖哪些设备 | 仅移动端 / 移动加笔记本 / 三档全覆盖 |
| Q5 | 动效偏好未知 | 动效强度 | 克制（150ms 内）/ 常规 / 明显（需减动效兜底） |

## 8 降级出口

门禁不通过时交付四项：已确认的视觉约束，例如设备档位与无障碍目标；缺失的输入项；可继续推进的最低版本，例如只给字体层级与间距 token；下一步建议。参数可先按缺省值给出，但须逐条标注默认值可调整。

## 9 反模式

- 用「现代、简洁、高级」代替具体取值。
- 为了装饰加入大量角落小字，降低传播与使用效率。
- 只写正常态，禁用态与错误态留给前端自行推断。
- 颜色按页面配，不按语义配，导致同类状态色不一致。
- 声称符合行业规范但未逐条对照，评审无法验证。
- 字号层级少于 5 级，页面看起来没有重点。

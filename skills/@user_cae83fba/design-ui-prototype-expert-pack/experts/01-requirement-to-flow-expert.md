# 需求到产品结构专家

通用追问触发条件、通用信息缺失处理与通用输出契约见 `playbooks/expert-router.md`，本文件只写本段特有内容。

## 1 阶段目标

把模糊想法、PRD 或会议纪要拆成目标、用户、页面、流程、状态和评审风险，交付可被评审者独立复述的产品结构。执行流程见 `workflows/requirement-intake.md`。

## 2 职能坐标

| 项 | 内容 |
|---|---|
| 阶段序 | 1/6 |
| 主职能 | 产品 |
| 前置 | 无，可独立从零起步 |
| 可跳过 | 否，跳过本段直接做 UI 会产出无目标的页面 |
| 下游 | 02 流程到线框图专家 |

## 3 输入契约

| 字段 | 类型 | 必需 | 缺失时处理 |
|---|---|---|---|
| userInput | 文本 | 是 | 阻断，E-INPUT-01 |
| outputPurpose | 枚举：评审 / 开发交接 / 演示 | 是 | 阻断，E-INPUT-02，未选时按评审处理并标注 |
| targetUsers | 文本或列表 | 是 | 阻断，E-INPUT-03，缺省按待确认角色占位并列入追问 |
| businessGoal | 文本 | 否 | 追问一次，仍缺失则标为假设并阻断进入 02 |
| prd | 文本或文件 | 否 | 带假设推进，标注影响范围 |
| screenshots | 图片文件 | 否 | 不可读时阻断，E-INPUT-04，要求补充页面说明 |
| existingPages | 文本或文件 | 否 | 不阻断，按全新设计处理 |
| industryContext | 文本 | 否 | 缺省不做行业声明，03 阶段需重问 |
| constraints | 文本 | 否 | 列入待确认事项 |

阻断规则：`userInput`、`outputPurpose`、`targetUsers` 任一缺失，停止主交付，只输出追问与降级说明。错误码定义见 `references/error-codes.md`，本条对应 E-INPUT-01、E-INPUT-02、E-INPUT-03。

## 4 输出契约

| 字段 | 类型 | 校验规则 | 落盘位置 |
|---|---|---|---|
| productGoal | 字符串 | 一句话可复述，禁写视觉或技术描述 | 需求确认表 `goal` |
| nonGoals | 数组 | 至少 2 条 | 需求确认表 `nonGoals` |
| users | 数组 | 每项含 role、task | 需求确认表 `users` |
| pages | 数组 | 每项 reason 必填且不少于 8 字 | `pages[].reason` |
| coveredStates | 数组 | 每页须含主态、空态、错态、加载态、权限态 | `pages[].coveredStates` |
| primaryActions | 数组 | 每页恰好 1 个 | `pages[].primaryActions` |
| mainPath | 数组 | 至少 2 步，可被复述 | 需求确认表 `mainPath` |
| assumptions | 数组 | 每条含 source 与 impact | 需求确认表 `assumptions` |
| openQuestions | 数组 | blocking 为 true 的项阻断下游 | 需求确认表 `openQuestions` |
| risks | 数组 | 至少 1 条，含 impact 与 suggestion | 需求确认表 `risks` |

结构校验用 `data/schemas/page-inventory.schema.json`。落盘文件名 `01-requirement-structure.md`。

## 5 标准输出

| 模块 | 内容 | 落盘字段 |
|---|---|---|
| 目标与非目标 | 本次要解决什么、不解决什么 | `goal` / `nonGoals` |
| 用户与场景 | 谁在什么场景下完成什么任务 | `users[].role` `users[].scenario` |
| 页面清单 | 页面、存在理由、入口、出口 | `pages[]` |
| 流程 | 主路径、分支、异常、空状态、权限状态 | `mainPath` / `branchPaths` / `exceptionPaths` |
| 风险 | 待确认业务规则、依赖、评审风险 | `risks` |

示例数据：`goal` 写运营在周会前判断跟进质量；`nonGoals` 写不做客户数据自动归因；`pages[0].reason` 写周会前需一眼识别滞后成员；`mainPath` 写先看红色超时区再下钻成员明细页。

## 6 专业判断标准

- 先确认北极星目标，不直接跳 UI 层。
- 页面必须服务用户任务，不能为了看起来完整而堆页面。
- 所有主路径必须有入口、动作、反馈和出口。
- 对不确定内容必须标注假设，不得伪装成事实。
- 非目标要写明本次不解决什么，用于挡住范围膨胀。
- 异常路径必须给出用户可执行的下一步，只写提示错误不合格。

### 本段量化锚点

- 页面清单每项均有存在理由，`reason` 无空值，无「常规需要」类措辞。
- 非目标条目数不少于 2 条。
- 假设项均标注来源与影响范围，来源取值限于用户原话、行业惯例、缺省默认。
- 主路径可由评审者一句话复述，无需回看表格。

## 7 追问规则

选项化提问，一次不超过 5 个，每题给 2 至 3 个候选便于快选。

| 编号 | 触发条件 | 问法 | 选项 |
|---|---|---|---|
| Q1 | 目标用户缺失 | 这份结构主要给谁看 | 运营执行层 / 业务管理者 / 外部客户 |
| Q2 | 输出用途缺失 | 产物准备用在哪一步 | 内部评审 / 研发交接 / 对外演示 |
| Q3 | 页面清单易膨胀 | 本次不解决哪些范围 | 暂不做移动端 / 暂不做数据导出 / 暂不做权限细分 |
| Q4 | 业务规则影响主路径 | 关键动作的规则由谁定 | 产品已定 / 需业务方确认 / 暂按常见规则假设 |
| Q5 | 截图意图不明 | 这批截图用来做什么 | 复盘问题 / 提炼设计系统 / 优化现有页面 |

## 8 降级出口

门禁不通过时交付五项，不进入页面清单主交付：当前可确认的信息并标注来源；信息缺口清单；需要用户补充的材料清单；可继续推进的最低版本，例如仅目标与非目标加主路径草案；下一步建议，说明补齐后回到本段第 1 步。降级状态下不得输出完整页面清单并暗示可直接进入 02。

## 9 反模式

- 只列首页、列表页、详情页，不说明每页服务什么任务。
- 把会议纪要里的形容词直接当页面目标。
- 页面数量对齐竞品，而不看用户任务是否需要。
- 假设写成陈述句，读者无法区分事实与推测。
- 把权限态和异常态留到 02 阶段再补。

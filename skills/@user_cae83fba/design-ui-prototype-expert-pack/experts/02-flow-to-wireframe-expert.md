# 流程到线框图专家

通用追问触发条件、通用信息缺失处理与通用输出契约见 `playbooks/expert-router.md`，本文件只写本段特有内容。

## 1 阶段目标

把已确认的页面与流程转成低保真线框图规格，优先解决信息架构和操作路径，不做视觉决策。执行流程见 `workflows/wireframe-to-ui.md` 第 1 至 2 步。

## 2 职能坐标

| 项 | 内容 |
|---|---|
| 阶段序 | 2/6 |
| 主职能 | 产品 + 设计 |
| 前置 | 01 的页面清单，含每页存在理由 |
| 可跳过 | 否，用户已有流程草图时可从本段起步，但需先补齐角色与异常状态 |
| 下游 | 03 线框图到 UI 规格专家 |
| 本段不做 | 配色、字号、组件视觉、代码 |

## 3 输入契约

| 字段 | 类型 | 必需 | 缺失时处理 |
|---|---|---|---|
| pages | 数组 | 是 | 阻断，E-INPUT-05，需先执行 01 |
| mainPath | 数组 | 是 | 阻断，E-INPUT-06，页面顺序无法确定 |
| users | 数组 | 是 | 阻断，E-INPUT-03，缺省按待确认角色占位 |
| coveredStates | 数组 | 是 | 不阻断，缺省按主态、空态、加载态、错态、权限态五项补齐并标注 |
| blocks | 数组 | 否 | 追问一次，仍缺失则由本段按用户任务推导并标注假设 |
| businessRules | 文本 | 否 | 列入 openQuestions，标 blocking |
| wireframeSource | 文本或图片 | 否 | 不阻断，按 blocks 推导 |
| outputPurpose | 枚举 | 否 | 缺省按评审处理 |

阻断规则：`pages` 与 `mainPath` 任一缺失，停止区块级输出，只交付信息架构缺口清单。错误码见 `references/error-codes.md`，本条对应 E-INPUT-05、E-INPUT-06。

## 4 输出契约

| 字段 | 类型 | 校验规则 | 落盘位置 |
|---|---|---|---|
| pages[].blocks | 数组 | 至少 2 项，顺序符合用户决策顺序 | 线框规格 `blocks` |
| blocks[].priority | 整数 | 取值 1 至 3，1 为最高 | `blocks[].priority` |
| pages[].primaryActions | 数组 | 恰好 1 个，含 name 与 result | `pages[].primaryActions` |
| pages[].secondaryActions | 数组 | 不得与主操作视觉同级 | `pages[].secondaryActions` |
| pages[].coveredStates | 数组 | 须含主态、空态、错态、加载态、权限态 | `pages[].coveredStates` |
| pages[].jumpTargets | 数组 | 目标须存在于 pages 中 | `pages[].jumpTargets` |
| pages[].entry | 字符串 | 写明来源页面或触发动作 | `pages[].entry` |
| pages[].exit | 字符串 | 同时写成功去向与失败去向 | `pages[].exit` |
| layoutDecisions | 数组 | 每项含 decision 与 reason | 线框规格 `layoutDecisions` |

结构校验用 `data/schemas/page-inventory.schema.json`。落盘文件名 `02-wireframe-spec.md`。

## 5 标准输出

| 页面 | 页面目标 | 区块 | 主要操作 | 次要操作 | 状态 | 跳转 |
|---|---|---|---|---|---|---|
| 成员明细页 | 定位跟进滞后的具体客户 | 筛选条、客户列表、批量操作条 | 标记已跟进 | 导出、转交 | 主态、空态、加载态、错态、权限态 | 质量看板页 |
| 客户档案页 | 确认单个客户的跟进历史 | 客户信息、跟进时间线、备注输入 | 保存备注 | 归档、查看历史 | 主态、空态、加载态、错态、权限态、冲突态 | 成员明细页 |

上表区块顺序即用户决策顺序：先筛选，再看列表，最后做批量操作。

## 6 专业判断标准

- 线框图不是视觉稿，重点是信息顺序、区块关系和操作优先级。
- 每个页面必须有主任务和主按钮。
- 复杂页面要先确定信息优先级，再决定布局。
- 必须覆盖空、错、加载、权限和冲突状态。
- 区块顺序按用户决策顺序排，不按视觉美观或后端表结构排。
- 每个布局决策都要写选型理由，例如为什么用筛选条而不是搜索框。

### 本段量化锚点

- 信息架构五层齐备：入口层、导航层、内容层、操作层、反馈层。
- 每页覆盖状态数不少于 4 个，含主态与空态。
- 每页主操作恰好 1 个，第二个主操作即判定不合格。
- 全部布局决策已选型并写明理由，无理由的决策项计为未完成。

## 7 追问规则

| 编号 | 触发条件 | 问法 | 选项 |
|---|---|---|---|
| Q1 | 主操作不明确 | 用户到这页最想完成哪件事 | 查看数据 / 录入信息 / 审批决策 |
| Q2 | 区块顺序有争议 | 首屏优先放哪块 | 筛选与汇总 / 明细列表 / 图表概览 |
| Q3 | 状态覆盖不足 | 这页最可能出现哪种异常 | 无数据 / 加载慢 / 操作失败 / 无权限 |
| Q4 | 布局选型未定 | 列表用卡片还是表格 | 表格密集 / 卡片可读 / 分页表格 |
| Q5 | 批量操作边界不清 | 批量操作是否需要权限控制 | 需要角色校验 / 仅管理员 / 不涉及 |

## 8 降级出口

门禁不通过时交付四项：已确认的页面目标清单；缺失的角色、路径或规则；需要用户补充的信息；可继续推进的最低版本，例如只给主路径页面的区块草图。不得在 `pages` 缺失时凭想象补全页面。

## 9 反模式

- 把所有信息平均堆成卡片，用户不知道先看什么、点什么。
- 区块顺序照搬后台菜单或数据库字段顺序。
- 一页放两个主按钮，主操作被稀释。
- 只画主态，把空态与错态留给开发自行发挥。
- 用视觉稿的阴影、圆角、配色掩盖信息结构未定。

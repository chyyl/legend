## 1. 主路径

以页面名序列表达，须可被评审者一步复述。

```
跟进质量看板  →  客户明细列表  →  跟进记录详情  →  新增跟进  →  返回列表
```

| 序号 | 页面 | 用户在此页要完成 | 出口去向 |
|---|---|---|---|
| 1 | 示例：跟进质量看板 | 示例：判断是否达标 | 示例：客户明细列表 |
| 2 | 示例：客户明细列表 | 示例：找到需跟进客户 | 示例：跟进记录详情 |
| 3 | 示例：新增跟进 | 示例：记录一次联系 | 示例：返回列表并刷新 |

## 2. 分支路径

| 触发条件 | 分支 | 路径 | 出口 |
|---|---|---|---|
| 示例：客户无跟进记录 | 有记录 | 示例：列表 → 详情 → 新增跟进 | 示例：返回列表 |
| 示例：客户无跟进记录 | 无记录 | 示例：列表 → 新增跟进（首条） | 示例：返回列表 |

## 3. 异常与恢复路径

每条须给出用户可执行的下一步。

```
数据源连接失败  →  错误态（错误条 + 重试）  →  重试  →  主态
```

| 触发条件 | 处理 | 恢复动作 | 恢复后去向 |
|---|---|---|---|
| 示例：指标接口超时 | 示例：显示错误条与重试按钮 | 示例：点击重试 | 示例：回到本页主态 |
| 示例：保存跟进失败 | 示例：表单内错误提示，保留已填内容 | 示例：修改后重新提交 | 示例：回到新增跟进主态 |
|  |  |  |  |

## 4. 权限分支

权限不足时显式呈现，不隐藏入口，不用 404 伪装。

```
权限校验  ──通过──→  页面主态
   │
   └──不通过──→  权限受限页（权限说明 + 申请入口 + 替代路径）
```

| 角色 | 可达路径 | 不可达页面 | 提示方式 |
|---|---|---|---|
| 示例：门店运营专员 | 示例：看板、列表、详情 | 示例：设置 | 示例：侧边导航保留设置项并说明缺少权限 |
|  |  |  |  |

# 完整示例：客户管理看板

## 1. 输入需求

业务团队需要一个桌面端客户管理看板，用来管理客户、识别高价值线索、分配跟进任务，并查看客户详情。第一版需要支持客户列表、客户详情、跟进任务和客户分层规则。

## 2. 关键假设

- 平台：桌面端 Web 管理后台。
- 用户：销售经理、客户经理、运营管理员。
- 目标：提高高价值客户的识别和跟进效率。
- 非目标：不替代完整 CRM，不处理账单，不处理合同审批。
- 数据来源和权限模型需要业务方进一步确认。

## 3. 产品结构

| 项目 | 内容 |
|---|---|
| 核心场景 | 管理者发现高价值客户，并分配跟进任务。 |
| 主路径 | 看板首页 → 客户列表 → 客户详情 → 创建跟进任务 → 成功提示。 |
| 分支路径 | 按客户分层筛选、导出列表、查看任务历史。 |
| 空状态 | 当前筛选条件下无客户，提供重置筛选操作。 |
| 加载状态 | 指标卡片和表格使用骨架屏。 |
| 错误状态 | 数据加载失败时允许重试，并给出支持提示。 |
| 权限状态 | 导出和任务分配需要经理权限。 |

## 4. 页面清单

| 页面 | 目标 | 主要操作 | 关键数据 | 状态 |
|---|---|---|---|---|
| 看板首页 | 展示总体情况和风险信号 | 查看高价值客户 | 指标、趋势、预警 | 加载、错误、无预警 |
| 客户列表 | 查找和比较客户 | 打开详情 / 分配任务 | 画像、价值、状态 | 空、筛选后无结果、无导出权限 |
| 客户详情 | 理解客户与历史记录 | 创建跟进任务 | 画像、时间线、订单、备注 | 加载、部分字段受限 |
| 任务抽屉 | 创建跟进任务 | 提交任务 | 负责人、截止日期、优先级、备注 | 校验、提交中、成功、失败 |
| 分层配置 | 维护客户分层规则 | 保存规则 | 条件、预览数量 | 草稿、校验失败、已保存 |

## 5. 线框图结构

### 看板首页

- 顶部摘要：客户总数、高价值客户数、逾期跟进数、转化趋势。
- 中部区域：预警列表和重点分层卡片。
- 底部区域：近期动态和客户列表快捷入口。

### 客户列表

- 筛选栏：分层、负责人、状态、价值区间、最近联系日期。
- 表格：客户、分层、价值分、负责人、最近联系、下一步动作。
- 行操作：查看详情、分配任务。
- 空状态：解释当前筛选结果为空，并提供重置操作。

### 客户详情

- 头部：客户名称、状态、价值分、负责人。
- 主标签页：概览、互动记录、订单、任务。
- 右侧抽屉操作：创建跟进任务。

## 6. UI 规格

| 区域 | 规则 |
|---|---|
| 视觉语气 | 专业、高效、可信，避免装饰性复杂度。 |
| 信息密度 | 表格工作流允许中高密度，但行高必须保证可读。 |
| 字体层级 | 页面标题 24px，区块标题 16px，正文和表格 14px，辅助信息 12px。 |
| 颜色 | 中性背景，蓝色作为主操作，橙色作为风险提醒，红色表示逾期或错误，绿色表示成功。 |

## 7. 设计系统片段

| 类型 | 名称 | 用途 |
|---|---|---|
| 颜色 token | color-primary | 主按钮、关键链接、当前选中状态 |
| 颜色 token | color-warning | 逾期、风险、即将超时 |
| 颜色 token | color-success | 保存成功、任务完成 |
| 间距 token | spacing-8 / 12 / 16 / 24 | 表格、卡片、区块之间的统一间距 |
| 组件 | 指标卡片 | 展示关键指标和变化趋势 |
| 组件 | 客户表格 | 承载筛选、排序、分页和行操作 |
| 组件 | 任务抽屉 | 在不中断上下文的情况下创建跟进任务 |
| 组件 | 状态标签 | 表达客户分层、跟进状态和风险等级 |

## 8. 前端交接要点

| 项目 | 说明 |
|---|---|
| 页面结构 | 看板首页、客户列表、客户详情、任务抽屉、分层配置。 |
| 数据假设 | 客户价值分、分层规则、负责人、互动记录来自后端接口。 |
| 权限规则 | 导出、分配任务、编辑分层规则需要权限校验。 |
| 埋点建议 | 筛选使用、客户详情打开、任务创建、导出点击、规则保存。 |
| 响应式 | 第一版以桌面端为主；小屏仅保证可读，不承诺完整移动端体验。 |
| 未确认项 | 分层算法、字段口径、导出范围、权限角色。 |

## 9. QA 检查

| 等级 | 检查项 | 结论 |
|---|---|---|
| P0 | 是否泄露真实客户信息或本机路径 | 必须无泄露 |
| P0 | 核心路径是否可闭环 | 看板 → 列表 → 详情 → 创建任务必须完整 |
| P1 | 空、加载、错误、无权限状态是否覆盖 | 必须覆盖主要页面 |
| P1 | 表格字段是否有业务口径 | 需要业务方确认 |
| P2 | 文案是否自然、可读、非技术化 | 建议评审前统一润色 |

## 9.1 可访问性检查（新增）

| 项目 | 要求 | 当前结论 |
|---|---|---|
| 文本对比度 | 正文 >= 4.5:1，关键控件 >= 3:1 | 通过（需在实现时复测） |
| 焦点可见 | 键盘聚焦时可见高亮 | 需前端实现 focus 样式并验证 |
| 键盘可达 | 看板 -> 列表 -> 详情 -> 任务抽屉可 Tab 到达 | 评审通过，待原型运行验证 |
| 状态冗余表达 | 不只靠颜色表达风险与错误 | 通过（风险标签配文案） |

## 9.2 响应式规则摘要（新增）

| 断点 | 布局 | 表格策略 | 主操作位置 |
|---|---|---|---|
| < 768 | 单列，过滤器折叠 | 优先字段保留，次要字段收起 | 底部吸附“新建任务” |
| 768-1279 | 双列，筛选栏固定 | 表格横向滚动可用 | 页面右上主操作 |
| >= 1280 | 三段式（筛选+列表+详情联动） | 全字段表格+冻结关键列 | 页面右上主操作 |

## 9.3 交互反馈时序（新增）

| 交互 | 即时反馈 | 成功反馈 | 失败反馈 | 目标时序 |
|---|---|---|---|---|
| 提交任务 | 按钮 loading | Toast + 抽屉关闭 | 错误提示 + 保留表单 | 150-300ms 出现反馈 |
| 保存分层规则 | 按钮 loading + 禁止重复点击 | 顶部成功提示 | 校验失败字段高亮 | 150-300ms 出现反馈 |

## 10. 下一步需要确认

1. 客户价值分和客户分层规则的业务口径。
2. 销售经理、客户经理、运营管理员的权限差异。
3. 是否需要移动端适配。
4. 是否允许导出客户数据，以及导出字段范围。
5. 任务提醒和逾期通知是否进入第一版。

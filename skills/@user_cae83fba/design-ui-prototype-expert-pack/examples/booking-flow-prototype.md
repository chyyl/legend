# 示例：预约流程原型

本示例演示流程型移动端预约场景的完整交付结构。重点是每页五状态逐条落地，避免只画主路径。

## 输入

| 项 | 内容 |
|---|---|
| 原始输入 | 用户需要在移动端网页预约一项服务。 |
| 目标用户 | 已在网页端浏览过服务项目、希望线下到店接受服务的普通消费者。 |
| 业务目标 | 让用户在一次会话内完成预约，减少到店后无法服务的情况。 |
| 非目标 | 不做服务项目的比价与推荐；不做多人在同一时段共同预约；不做会员权益与优惠券。 |
| 使用端 | 移动端网页，容器宽度 320 至 430px。 |
| 交付物类型 | 产品结构、页面清单、线框规格、可评审原型、交互说明。 |
| 输入缺口 | 取消时限、违约处理、时段是否随门店浮动，三项待业务方确认。 |

## 产品结构

| 项 | 内容 |
|---|---|
| 目标 | 用户能选到可用时段并提交一次可核对的预约。 |
| 非目标 | 不处理支付；不处理多门店比价；不提供可用性测试结论。 |
| 用户 | 普通消费者一人操作，无需注册即可浏览，下单时需联系方式。 |
| 主场景 | 用户在到店前一日或当日选定服务与时段，提交后获得凭据。 |
| 主路径 | 服务选择 → 时间选择 → 填写信息 → 订单确认 → 预约成功。 |
| 分支路径 | 更换服务、修改时段、修改联系方式、返回上一步保留已填内容。 |
| 空状态 | 所选服务当前无可约时段，需给出可执行的下一步。 |
| 加载状态 | 时段列表与提交结果需要等待，等待期间不可重复提交。 |
| 错误状态 | 时段被抢占、提交失败、联系方式格式错误三类需分别处理。 |
| 权限状态 | 同一手机号在同一服务下已有未完成预约时需拦截。 |
| 关键风险 | 冲突处理与取消文案未定，会直接影响主路径的可用性判断。 |

## 页面清单

| 页面 | 页面目标 | 存在理由 | 入口 | 主要操作 | 覆盖状态 |
|---|---|---|---|---|---|
| 服务选择 | 让用户确定要预约的服务项目 | 服务时长与价格差异大，需先锁定项目再选时段 | 首页服务列表 | 选择服务 | 主态、空态、加载态、错态 |
| 时间选择 | 找到可用的到店时段 | 时段是本场景的核心决策对象，不可与服务选择合并 | 服务选择页 | 确认时段 | 主态、空态、加载态、错态、权限态 |
| 信息填写 | 收集到店必要信息 | 需要联系方式确认身份，缺此信息无法到店通知 | 时间选择页 | 提交信息 | 主态、加载态、错态、权限态 |
| 订单确认 | 让用户在提交前核对全部信息 | 提交前的最后核对环节，可显著降低填错率 | 信息填写页 | 确认提交 | 主态、加载态、错态 |
| 结果页 | 给出凭据与后续动作 | 用户需要凭据到店，也需要知道如何改期 | 订单确认页 | 查看凭据 | 主态、加载态、错态 |
| 已有预约拦截 | 阻止重复预约同一服务 | 同一手机号重复预约会导致到店冲突 | 任一提交动作触发 | 查看已有预约 | 主态、权限态 |

## 五状态覆盖明细

### 服务选择

| 状态 | 文案 | 交互 |
|---|---|---|
| 空态 | 当前城市暂无可预约的服务项目，可切换城市或留下联系方式，到新服务上线时通知你 | 主操作降级为「切换城市」，次操作提供「到货通知」登记入口 |
| 加载态 | 正在获取服务项目 | 骨架卡片占位，保持卡片高度不跳动 |
| 错态 | 服务项目加载失败，请检查网络后重试 | 主操作变为「重新加载」，保留已选城市 |
| 权限态 | 本页无需权限，不设拦截 | 不展示任何权限相关内容 |

### 时间选择

| 状态 | 文案 | 交互 |
|---|---|---|
| 空态 | 该服务今天没有可约时段，可查看明天时段或改为电话预约 | 主操作降级为「查看明天」，次操作给出门店电话 |
| 加载态 | 正在获取可约时段 | 按时段骨架占位，禁止在加载中点击确认 |
| 错态 | 时段数据获取失败，重新加载后可能已有名额被占用 | 重新加载后高亮刷新前已选时段是否仍可用 |
| 权限态 | 你已有一个该服务的未完成预约，可先完成或取消 | 主操作改为「查看已有预约」，本时段确认按钮置为禁用并说明原因 |

### 信息填写

| 状态 | 文案 | 交互 |
|---|---|---|
| 空态 | 带必填标记的字段为空时不视为空态，提交时逐字段提示，不设整页空态 | 不适用 |
| 加载态 | 正在校验手机号格式 | 失焦后触发，输入中不触发，避免逐字报错 |
| 错态 | 手机号格式不正确，需填写 11 位手机号 | 错误落在字段下方，输入框描边转错误色，焦点自动移到首个错误字段 |
| 权限态 | 手机号已被其他账号绑定，可更换手机号或联系门店协助 | 主操作改为「更换手机号」 |

### 订单确认

| 状态 | 文案 | 交互 |
|---|---|---|
| 空态 | 上游页面数据缺失时不进入本页，返回上一步并提示 | 不适用 |
| 加载态 | 正在校验时段是否仍可预约 | 校验期间确认按钮禁用，避免重复提交 |
| 错态 | 该时段刚被预约完成，请重新选择时段 | 保留用户已填写的联系方式，回退到时间选择页并高亮冲突时段 |
| 权限态 | 无需额外权限，沿用上游时段归属 | 不展示 |

### 结果页

| 状态 | 文案 | 交互 |
|---|---|---|
| 空态 | 提交结果未返回时不展示空白页，显示等待状态并提供手动刷新 | 等待超过 10 秒后主动提示可刷新 |
| 加载态 | 正在获取预约凭据 | 凭据骨架占位 |
| 错态 | 预约可能已提交，凭据获取失败。请先在「我的预约」中确认，避免重复预约 | 主操作为「查看我的预约」，不提供「重新提交」 |
| 权限态 | 凭据页需凭手机号后四位验证后方可查看他人手机号下的预约 | 验证失败给三次机会，超出后只显示本机预约 |

## 响应式三档

| 断点 | 布局 | 主操作位置 |
|---|---|---|
| 至 767px，单列 | 步骤条在顶部横向排列，步骤说明简化为当前步骤名；时间卡片单列纵向排列，每张卡片占满容器宽度 | 底部固定操作条，主操作占满宽度，次操作置于主操作上方 |
| 768 至 1279px，两列 | 时间选择与订单摘要可左右并排，摘要宽度不超过容器 40% | 主操作置于摘要卡片内右下角，随内容滚动 |
| 1280px 及以上，三段式 | 左侧步骤内容，右侧订单摘要固定，摘要可展开查看完整明细 | 主操作固定在右侧摘要底部 |

三档下主路径均需可完成。窄屏时摘要折叠为首行一行摘要，点击后展开，不阻断提交。

## 交互反馈时序

| 交互对象 | 触发 | 即时反馈 | 成功反馈 | 失败反馈 | 期望时序 |
|---|---|---|---|---|---|
| 服务卡片 | 点击 | 描边转主色，选中态标记出现 | 进入时间选择页 | 不适用 | 80 至 150ms 内给出选中反馈 |
| 时段卡片 | 点击 | 卡片转选中态，右侧出现确认入口 | 确认入口可点击 | 选中的时段已被占用时给出行内提示 | 80 至 150ms 内给出选中反馈 |
| 确认预约 | 点击 | 按钮进入加载态并禁用 | 跳转结果页并显示凭据 | 时段冲突时回退时间选择页并高亮冲突项 | 150 至 300ms 内出现加载反馈 |
| 手机号输入 | 失焦 | 字段下方出现校验结果 | 显示格式正确 | 显示具体规则与正确示例 | 300ms 内出结果，错误不闪烁 |
| 返回上一步 | 点击 | 返回并保留已填内容 | 顶部提示已保留填写内容 | 保留失败时提示内容将丢失 | 150ms 内完成页面切换 |

## 无障碍验收

| 检查项 | 规则 | 证据 | 结论 |
|---|---|---|---|
| 正文对比度 | 不低于 4.5:1 | 订单摘要正文与背景的比值记录在 UI 规格的 contrastChecks 中 | 待实现后复测 |
| 关键控件对比度 | 按钮边界与图标不低于 3:1 | 主操作按钮描边与填充色分别记录比值 | 待实现后复测 |
| 触控尺寸 | 可点击区域不小于 44 乘 44px | 时段卡片高度按 48px 设计，含 4px 间隔 | 设计已满足 |
| 焦点可见 | 键盘聚焦时有可见轮廓 | 焦点态样式写入组件状态表的 focus 项 | 待实现后复测 |
| 状态冗余表达 | 状态不能只靠颜色区分 | 冲突提示为错误色加叉号图标加文字三通道 | 设计已满足 |
| 表单错误定位 | 错误落在字段附近，不做顶部泛提示 | 错误文案位置见信息填写页状态表 | 设计已满足 |
| 步骤条语义 | 当前步骤有可读文本，不只用圆点 | 步骤条附文字标签与 aria-current | 待实现后复测 |

## 待确认问题

| 编号 | 问题 | 选项 | 影响 |
|---|---|---|---|
| Q1 | 用户可提前多久预约 | 7 天 / 30 天 / 不限 | 影响时间选择页的日期范围与空态文案 |
| Q2 | 同一手机号已有未完成预约时的处理 | 拦截并引导查看 / 允许同时预约多个时段 / 提示但可继续 | 影响权限态与信息填写页的提交行为 |
| Q3 | 门店是否需要停用时段的操作 | 需要，运营侧可维护 / 不需要，由固定排班生成 | 影响时段列表的数据来源与错态类型数量 |
| Q4 | 取消预约的时限 | 到店前 2 小时 / 到店前 24 小时 / 不可取消 | 影响订单确认页与结果页的文案 |

四个问题中 Q1 与 Q2 阻断进入开发，Q3 与 Q4 可先按选项 A 推进并标注为假设。

# 回归用例集

在发布前或技能更新后执行本用例集，验证路由、输出契约与降级行为是否稳定。机器可读版本见 `tests/regression-cases.yaml`，执行记录模板见 `tests/result-template.md`。

## 执行方式

1. 按 R1 至 R12 顺序逐条执行，不抽样。
2. 每条核对四项：预期路由命中、最低输出覆盖、结论证据化、信息不足时正确降级。
3. 结果填入 `tests/result-template.md`。
4. 12 条执行完毕后再判定发布结论，判定标准见 `qa/release-gate.md`。

## R1 一句话想法转产品结构

**输入：** 我想做一个给运营团队看的客户跟进质量看板，帮我整理成可评审的产品结构，不要直接开始画 UI。

**预期路由：** 01

**最低输出：** 目标与非目标、用户与场景、页面清单、主路径与异常、假设与待确认。

**通过条件：** 未直接跳到视觉稿，假设已标注来源。

## R2 预约 PRD 转流程与线框

**输入：** 下面是一段预约预订 PRD，请提取页面清单、主路径和每个页面的线框图规格。请覆盖空状态、加载状态和错误状态。

**预期路由：** 01 到 02

**最低输出：** 页面清单、主路径、区块结构、主次操作、跳转、五种必备状态。

**通过条件：** 每页有目标且存在理由，关键状态齐备。

## R3 B2B 线框转 UI 规格

**输入：** 这是一个 B2B 后台的低保真线框图说明，请生成 UI 规格。请给出字体、颜色、间距、组件状态和可读性建议。

**预期路由：** 03

**最低输出：** 视觉方向、字体层级、颜色语义、间距 token、组件状态、参数建议段。

**通过条件：** 回答含具体数值，不是泛化形容词。

## R4 三个 UI 页面转设计系统

**输入：** 我有三个 UI 页面，请帮我提炼成一个临时设计系统，包含 token、组件清单、组件状态和使用边界。

**预期路由：** 04

**最低输出：** 三层 token、组件清单、状态矩阵、不可复用清单、前端映射。

**通过条件：** token 含语义用途，组件覆盖七态，语义占比不低于 80%。

## R5 HTML 原型 QA 评审

**输入：** 请评审这个 HTML 原型是否可以进入评审。请给出通过、带风险通过或不通过的结论，并列出 P0 至 P3 问题。

**预期路由：** 06

**最低输出：** 结论、P0 至 P3 问题表、证据位置、影响与建议、七维评分与扣分依据。

**通过条件：** 缺证据时不给通过类结论；文件打不开时明确说明缺运行时检查。

## R6 金融类后台 UI 规格

**输入：** 这是金融后台的线框图，请给 UI 规格和参数建议。

**预期路由：** 03

**最低输出：** 参数建议段加金融行业反模式逐条对照。

**通过条件：** 金融反模式逐条给出结论，命中项写调整后取值。

## R7 医疗类产品 UI 规格

**输入：** 这是医疗类产品后台的线框图，请给 UI 规格和参数建议。

**预期路由：** 03

**最低输出：** 参数建议段加医疗行业反模式逐条对照。

**通过条件：** 医疗反模式逐条给出结论，命中项写调整后取值。

## R8 含确认表的原型评审

**输入：** 下面有需求确认表和对应的 HTML 原型，请对照需求评审实现情况。

**预期路由：** 06

**最低输出：** 需求覆盖矩阵，逐条需求有实现状态与证据。

**通过条件：** 需求条目覆盖率 100%，无整体打勾式结论。

## R9 窄屏与放大字号弹性检查

**输入：** 请检查这个原型在窄屏和字号放大到 200% 时的表现。

**预期路由：** 05 或 06

**最低输出：** 弹性文本八条的逐条落地方式。

**通过条件：** 六条各有方式，不写笼统的自适应。

## R10 信息不足时的降级交付

**输入：** 只有这张截图，你先看看能做什么。

**预期路由：** 01

**最低输出：** 分诊结论、信息缺口清单、需补充材料、最低版本方案。

**通过条件：** 走降级出口，未强行输出完整页面清单。

## R11 只要设计系统不要原型

**输入：** 我只要一套设计系统规范，不需要原型，也不需要交接文档。

**预期路由：** 04

**最低输出：** 设计系统产物加路由说明。

**通过条件：** 路由未越界到 05 与 06，并说明跳过原因。

## R12 已有 DESIGN.md 落地页面

**输入：** 我们有品牌设计规范文档，请据此把页面落成 UI 规格与前端交接说明。

**预期路由：** 03 到 05

**最低输出：** 品牌样本取用说明、UI 规格、交接清单。

**通过条件：** 品牌样本路径可达且有效，规范规则被正确引用，未声称已覆盖全部规范。

# 交付检查清单

本文件定义交付前的逐项检查口径。P0 至 P3 四级问题分级适用于全部六段产物，评分操作见 `qa/scoring-workflow.md`，发布门禁见 `qa/release-gate.md`。

## 使用方式

1. 逐项检查，每项给出「通过 / 不通过 / 不适用」。
2. 命中问题即登记严重度与证据位置，证据精确到文件与行号或区块名。
3. 存在任一 P0 时，结论不得为通过或带风险通过。
4. 不适用项须写明原因，不允许留空跳过。

## P0 阻断项

出现以下任一问题，不应判定为通过：

- 没有读取目标文件、页面或用户提供材料，却声称已经完成评审。
- 交付物中出现本机绝对路径、用户名、隐私信息或客户敏感信息。
- 技能包缺少根入口 `SKILL.md`，或 YAML front matter 无法解析。
- ZIP 内包含隐藏文件、嵌套 ZIP、Office 文件、图片、PDF 等上传风险文件。
- 原型主路径无法完成，关键按钮或跳转缺失。
- 必需输入字段缺失仍继续主交付，且未按 `references/error-codes.md` 登记 E 码。
- 必需状态缺失且未标注风险：空态、加载态、错误态、权限态任一未覆盖。
- 把评审级原型包装成生产级代码，未声明 `scopeBoundary`。
- 结论与证据矛盾，例如证据显示关键交互缺失却给带风险通过。
- 出现未授权的第三方品牌词或商标。

## P1 主要风险

出现以下问题时，应标记为带风险通过或不通过：

- 页面结构与用户目标不匹配。
- 组件状态不完整，缺聚焦、禁用、加载、错误任一态。
- 前端交接缺少字段、事件、校验或数据假设。
- 文字过小，真实预览下不可读。
- 普通文本对比度低于 4.5:1，或关键控件与图标对比度低于 3:1。
- 主路径关键交互无法通过键盘完成，或焦点不可见。
- 仅依赖颜色区分错误、成功、警示状态。
- 移动端关键点击区域过小，低于 44x44 视为风险。
- 语义 token 占比低于 80%，或 token 只有原始值没有语义用途。
- 断点表缺档，四档中任一档未给布局变化。
- 假设未标注来源与影响范围。

## P2 优化项

以下问题不一定阻断交付，但建议修复：

- 命名不统一。
- 文案风格不一致。
- 缺少更完整的示例。
- 某些设计 token 还没有语义化。
- QA 证据不够细。
- 区块顺序未说明理由。
- 埋点建议缺失或未与主操作对应。
- 页面清单未标注不可复用元素。

## P3 打磨项

P3 不影响评审结论，可在后续迭代处理：

- 圆角、阴影、过渡时长等细节参数未对齐设计系统。
- 图标风格混用，线性与面状混排。
- 空态插图风格不统一。
- 术语大小写或中英文空格不统一。
- 次要文案语气偏生硬。
- 表格列宽在笔记本档轻微拥挤，但不影响阅读与操作。
- 缺少深色模式适配说明，当前版本未要求。
- 动效曲线未统一，走的是相近但不同的缓动。

## 通过条件

交付物可以判定为通过，需要同时满足：

- 主任务路径可以完成。
- 关键页面与状态覆盖完整。
- 输出契约中要求的核心信息已提供。
- 风险、假设和待确认事项被清楚标注。
- 没有 P0 阻断项。
- 无障碍关键项可证明达标：对比度、焦点可见、键盘可达、状态冗余表达。

## 不通过条件

出现以下情况，应判定为不通过：

- 没有足够证据支撑结论。
- 主流程无法完成。
- 关键页面或状态缺失。
- 用户可能误以为评审级材料已经可直接上线。
- 评分低于 60 分，按 `qa/scoring-workflow.md` 建议回退上一阶段。

## 降级交付

当资料不足、权限受限或文件无法读取时，应交付降级版本：

- 当前可确认的信息。
- 不能确认的信息。
- 初步风险判断。
- 需要用户补充的材料。
- 下一步建议。

降级交付的结论只能是不通过或无法判定，不得给通过类结论。

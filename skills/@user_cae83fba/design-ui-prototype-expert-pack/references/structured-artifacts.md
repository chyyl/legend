# 结构化产物规范

本文件定义 5 份结构化产物的生成时机、必填字段、消费方与版本约定。落盘命名与格式见 `references/output-conventions.md`。

## 0. 五份产物速查

| 编号 | 产物 | 生成阶段 | 主要消费方 |
|---|---|---|---|
| A1 | 需求确认表 | 01 段 | 02 段产品结构、需求评审会 |
| A2 | 页面清单 | 02 段 | 03 段线框、研发排期 |
| A3 | 设计 token | 04 段 | 05 段原型、前端实现 |
| A4 | 前端交接清单 | 05 段 | 前端开发、接口联调 |
| A5 | 需求覆盖矩阵 | 06 段 | 评审结论、验收 |

## 1. A1 需求确认表

| 项 | 内容 |
|---|---|
| 生成时机 | 01 段追问结束、MRC 门禁通过且用户确认后 |
| 必填字段 | 序号、维度、需求点、需求描述、目标用户、优先级、需求来源、状态 |
| 可选字段 | 用户场景、用户价值、依赖约束、冲突说明 |
| 消费方 | 02 段产品结构、需求评审 |
| 校验方式 | 结构对照 `data/schemas/` 下对应 Schema（可用时） |

维度取值范围：基础信息、目标用户、核心功能、目标价值、非目标、使用场景、角色权限、依赖约束。

状态取值：待确认、已确认、冲突。

## 2. A2 页面清单

| 项 | 内容 |
|---|---|
| 生成时机 | 02 段产品结构完成后、进入线框设计前 |
| 必填字段 | 页面名、页面目标、入口、主要操作、所需数据、需覆盖状态、页面存在理由 |
| 可选字段 | 出口、备注、责任端（Web / 移动 / 小程序） |
| 消费方 | 03 段线框、研发排期、设计评审 |
| 通过条件 | 见 `references/product-wireframe-playbook.md` 第 4 节页面清单 gate |

需覆盖状态至少含主状态、空状态、错误状态、加载状态、权限状态五项（对应红线 R4）。

## 3. A3 设计 token

| 项 | 内容 |
|---|---|
| 生成时机 | 04 段，需跨页面复用时生成 |
| 必填字段 | token 名、值、语义用途、使用场景、不适用场景 |
| 可选字段 | 参考来源、对比度实测值、复用判定 |
| 消费方 | 05 段原型、前端实现（CSS 变量或 Tailwind token） |
| 校验方式 | token 必须有三层（原始值、语义、组件），只有原始值的表不通过 |

复用判定取值：可复用、不可复用、待确认。

## 4. A4 前端交接清单

| 项 | 内容 |
|---|---|
| 生成时机 | 05 段，UI 规格确认后 |
| 必填字段 | 组件或页面名、属性与数据、事件、接口依赖、响应式规则 |
| 可选字段 | 埋点、状态机、验收用例、风险 |
| 消费方 | 前端开发、接口联调、测试 |
| 不通过条件 | 交互未说明目标元素与预期结果；把评审级原型描述为生产级代码 |

## 5. A5 需求覆盖矩阵

| 项 | 内容 |
|---|---|
| 生成时机 | 06 段评审开始前 |
| 必填字段 | 需求编号、需求点、对应产物章节、覆盖状态、备注 |
| 覆盖状态取值 | 已覆盖、部分覆盖、未覆盖 |
| 消费方 | 评审结论、验收 |
| 通过条件 | 每一项需求都能对应到具体章节，无未覆盖项（对应检查表 C10） |

## 6. 产物依赖关系

```
A1 需求确认表
  └→ A2 页面清单
        └→ A3 设计 token
              └→ A4 前端交接清单
                    └→ A5 需求覆盖矩阵
```

上游产物变更时，下游产物须同步修订并记录变更。修订后在「变更记录」行追加一行，写明变更项、影响范围与处理动作。

## 7. 版本约定

| 项 | 规则 |
|---|---|
| 版本号 | 与技能包版本对齐，便于追溯 |
| 修订标记 | 字段或条目级修订追加版本后缀，如 v1.2.0-2 |
| 状态字段 | 产物内每条记录带状态，取值与各产物定义一致 |
| 冲突项 | 未解决冲突不进入下游产物，须先在 A1 解决 |
| 待确认项 | 允许带入下游，但须在产物内单列「待确认事项」小节 |

# 前端原型 QA 指南

## 1. 评审级原型的边界

评审级原型用于讨论页面结构、视觉、交互和状态，不等同于生产级代码。若要上线，需要补齐工程架构、接口、权限、错误码、测试和部署要求。

## 2. 结构检查

需要确认：
- 页面根节点存在。
- 主要区块存在。
- 按钮、表单、表格、弹窗等关键元素存在。
- 选择器与脚本引用一致。
- 没有孤立的无效元素。
- 页面主路径的入口、关键动作、结果反馈在结构上可闭环。

## 3. 交互检查

需要确认：
- 点击后有明确反馈。
- 表单校验有效。
- 弹窗能打开和关闭。
- 状态变化符合预期。
- 错误提示能被用户理解。
- 主按钮、次按钮、危险操作按钮行为清晰且互不冲突。

交互最小动作集（建议逐项打勾）：
- 打开弹层 -> 关闭弹层。
- 表单校验失败 -> 修正 -> 成功提交。
- 切换筛选/分页 -> 列表刷新。
- 权限不足场景 -> 明确阻断反馈。
- 异步请求失败 -> 可重试或可回退。

## 4. 响应式检查

至少检查：
- 桌面宽屏。
- 普通笔记本宽度。
- 移动端或窄屏。

关注：文字是否溢出、表格是否可用、主按钮是否仍然明显。

推荐检查宽度：
- 390（移动端窄屏）。
- 1024（普通笔记本）。
- 1440（桌面宽屏）。

每个宽度至少确认：
- 主路径可完成。
- 关键控件可见且可点击。
- 主要数据不因布局变化而失真或不可读。

## 5. 视觉检查

需要确认：
- 字号足够大。
- 对比度足够。
- 间距统一。
- 组件风格一致。
- 页面主次清楚。

建议门槛：
- 普通文本对比度 >= 4.5:1。
- 大文本和关键图标/控件 >= 3:1。
- 关键文本不使用小于 12px 的装饰字体。

## 6. 可访问性与可操作性检查

至少覆盖：
- 键盘可到达主要交互（Tab 顺序合理）。
- 聚焦态可见，不隐藏焦点。
- 状态反馈不只依赖颜色。
- 可点击区域在移动端建议 >= 44x44。
- 降低动态偏好（reduced motion）场景下仍可完成任务。

## 7. 动效与性能检查

建议检查：
- 常规交互动效时长是否在 100-300ms 区间。
- 关键反馈是否过慢（>500ms 容易造成迟滞感）。
- 动画是否优先使用 transform/opacity。
- 列表加载是否优先使用骨架屏而非长时间转圈。
- 资源是否明显过重（字体过多、首屏大图未优化等）。

## 8. 结论格式

使用以下三类结论：
- 通过：没有 P0，P1 风险可控。
- 带风险通过：没有 P0，但存在需要评审确认的 P1。
- 不通过：存在 P0，或主路径无法完成。

# 输出约定

本文件定义 7 类交付物的命名、格式、落盘目录、拆分粒度与双份输出一致性要求。

## 1. 七类产物与命名规则

| 编号 | 产物类型 | 命名规则 | 格式 |
|---|---|---|---|
| O1 | 需求确认表 | `{项目名}-需求确认表-{日期}.md` / `.json` | Markdown + JSON |
| O2 | 页面清单 | `{项目名}-页面清单-{日期}.md` / `.json` | Markdown + JSON |
| O3 | 线框规格 | `{项目名}-线框规格-{日期}.md` | Markdown |
| O4 | UI 规格 | `{项目名}-UI规格-{日期}.md` | Markdown |
| O5 | 设计 token | `{项目名}-设计token-{日期}.md` / `.json` | Markdown + JSON |
| O6 | 前端交接清单 | `{项目名}-交接清单-{日期}.md` / `.json` | Markdown + JSON |
| O7 | 评审报告 | `{项目名}-评审报告-{日期}.md` | Markdown |

日期格式统一为 `YYYY-MM-DD`。项目名取用户项目名称，不含空格与特殊符号。

## 2. 格式规范

| 产物 | Markdown 要求 | JSON 要求 |
|---|---|---|
| O1、O2 | 表格为主，列顺序按 `references/structured-artifacts.md` 定义 | 数组或对象，顶层含 `version` 与 `generated_at` |
| O5 | token 三层表格 | `tokens` 分原始值、语义、组件三组 |
| O6 | 交接表 + 状态机表 | `components` 数组，每项含 `props` / `events` / `apis` |
| O7 | 结论 + P0/P1/P2 表 + 评分表 | 不要求 JSON |

JSON 统一 UTF-8 编码，两空格缩进，不含注释与尾随逗号。

## 3. 落盘目录

| 情形 | 目录 |
|---|---|
| 用户指定输出目录 | 使用用户指定目录 |
| 用户未指定 | 先询问，不自行选定系统目录 |
| 同一任务的全部产物 | 放在同一目录下，按命名规则区分 |

## 4. 拆分粒度

| 产物 | 粒度规则 | 超过阈值时 |
|---|---|---|
| O1、O2 | 单文件 | 不拆分，条目数超 80 行时按维度分组小节 |
| O3、O4 | 按页面拆分为小节 | 页数超 10 页时按模块拆为多文件，文件名前加模块名 |
| O5 | 单文件 | token 数超 150 条时按三层拆为三个文件 |
| O6 | 单文件 | 组件数超 40 个时按模块拆分 |
| O7 | 单文件 | 不拆分 |

## 5. 双份输出一致性

O1、O2、O5、O6 默认同时输出 Markdown 与 JSON 两份。

| 规则 | 说明 |
|---|---|
| D1 | 两份内容必须一致，JSON 字段与 Markdown 表格列一一对应 |
| D2 | Markdown 供人阅读，可加说明与备注列 |
| D3 | JSON 供下游工具消费，不加注释性文字 |
| D4 | 只保留一份会导致下游无法消费，两份都需产出 |
| D5 | 修订时两份同步修订，版本号保持一致 |
| D6 | 校验方式：以 JSON 为准，Markdown 出现 JSON 中没有的字段视为不一致 |

## 6. 版本与追溯

| 项 | 规则 |
|---|---|
| 版本号 | 与技能包版本对齐，格式 v1.2.0 |
| 文件名日期 | 首次生成日期，修订不改变文件名，另在文内标注修订日期 |
| 修订记录 | 每份产物文末保留「变更记录」表，记录变更项、影响范围、处理动作 |
| 引用 | 产物中引用其他产物时写文件名，不用「之前那份」等模糊表述 |

## 7. 脱敏与合规

| 要求 | 说明 |
|---|---|
| 路径 | 产物内引用文件用相对路径，不写本机绝对路径 |
| 人员 | 不写真实姓名与用户名 |
| 客户 | 不写真实客户名与内部项目代号 |
| 外部资料 | 引用公开仓库与规范时写公网 URL，属正常参考资料 |
| 缺口 | 未覆盖内容显式列入「已知缺口」，不静默省略 |

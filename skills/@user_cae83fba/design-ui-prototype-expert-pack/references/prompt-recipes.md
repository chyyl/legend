# 常用提问范式

当用户不知道如何提出原型、UI 规范、设计系统、前端交接或 QA 评审需求时，可以参考以下提问模板。这里的“路由”指技能内部建议进入的阶段模块，普通用户不需要理解模块实现细节。

## 范式 1：从想法到可评审原型方案

**提问示例：**
> 我有一个初步想法：为运营团队做一个客户跟进质量看板。请先不要直接画 UI，先帮我整理目标、非目标、用户角色、核心场景、页面清单、主路径、异常状态、需要补充的问题，并给出可进入原型评审的结构化方案。

**适用场景：**
- 用户只有一句话或粗略想法。
- 产出用于产品 / 设计评审，而不是直接开发。

**建议路由：**
01。如需要线框图，再进入 02。

## 范式 2：从 PRD 提取页面清单与流程

**提问示例：**
> 请根据下面这段 PRD，提取用户目标、角色、页面清单、主路径、分支路径、异常状态、空状态、权限差异和评审风险。请明确哪些内容来自原文，哪些是你的假设。

**适用场景：**
- 已有 PRD、需求说明或会议纪要。
- 需要先把需求拆成可设计的页面与流程。

**建议路由：**
01，然后按需要进入 02。

## 范式 3：从流程到线框图规格

**提问示例：**
> 请把下面的用户流程转成低保真线框图规格。请输出每个页面的目标、信息区块、主要操作、次要操作、跳转关系、空状态、加载状态、错误状态和评审注意点。

**适用场景：**
- 已有页面清单或用户流程。
- 需要先评审信息架构，不急着做视觉。

**建议路由：**
02。

## 范式 4：从线框图到 UI 规范

**提问示例：**
> 请基于下面的线框图说明，输出 UI 设计规格。请包含视觉方向、字体层级、颜色规则、间距规则、组件样式、状态变化、可读性与无障碍注意事项。不要只写“高级、现代、简洁”，请给出具体可执行决策。

**适用场景：**
- 已有线框图或页面结构。
- 需要给设计师或原型制作提供视觉规则。

**建议路由：**
03。

## 范式 5：从现有页面提炼设计系统

**提问示例：**
> 我会提供 3 个已有 UI 页面，请帮我提炼一个临时设计系统。请输出颜色、字体、间距、语义 token、组件清单、组件状态、使用边界和需要统一的问题。如果页面不足 3 个，请标注为临时版本。

**适用场景：**
- 已有截图、页面稿或前端页面。
- 需要沉淀统一规范，而不是只评价单页美观。

**建议路由：**
04。

## 范式 6：从 UI 规范到前端交接

**提问示例：**
> 请把下面的 UI 规范整理成前端交接说明。请包含页面结构、组件映射、字段与数据假设、状态表、响应式规则、埋点建议、验收用例和已知缺口。请明确哪些内容还不能进入生产开发。

**适用场景：**
- UI 规范已经相对明确。
- 需要交给前端做评审级原型或开发前评估。

**建议路由：**
05。生产级实现需要进入独立的软件工程流程。

## 范式 7：审查 HTML/CSS/JS 原型

**提问示例：**
> 请审查这个 HTML/CSS/JS 原型是否达到评审标准。请检查页面节点、选择器、交互状态、响应式、文案可读性、视觉一致性和运行时风险。最后给出“通过 / 带风险通过 / 不通过”的结论，并说明证据。

**适用场景：**
- 已有原型文件或页面链接。
- 需要判断是否能进入评审，而不是只看代码语法。

**建议路由：**
06。

## 范式 8：信息不完整时

**回复模板：**
> 当前信息还不足以直接进入最终交付。我会先基于已知内容做一个“带假设的初版”，同时列出必须补充的问题。若这些假设影响关键决策，我会先停在方案层，不直接生成 UI 或代码。

**建议路由：**
先使用输入分诊，再进入必要模块。

## 范式 9：用户要求生产级代码时

**回复模板：**
> 本技能可以生成评审级原型、设计说明和前端交接清单，但不直接承诺生产级代码。若要进入生产开发，需要补充接口契约、权限规则、错误码、数据字典、测试用例、部署要求和工程规范。

**建议路由：**
05 用于交接说明；生产实现需要转入软件工程任务。

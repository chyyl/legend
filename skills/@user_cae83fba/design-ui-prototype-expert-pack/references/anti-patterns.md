# 反模式

每条含现象、后果、改正动作三段。现象可观察、后果可描述、动作可执行。

## 0. 使用方式

按行业类别定位候选条目，再逐条对照 `references/pre-delivery-checklist.md`。

| 行业类别 | 优先对照条目 |
|---|---|
| 金融银行保险 | AP2、AP5、AP6、AP7、AP12、AP13、AP14 |
| 医疗健康 | AP1、AP3、AP4、AP6、AP11、AP12、AP15 |
| 企业级 SaaS | AP1、AP5、AP6、AP7、AP8、AP10、AP12 |
| 政务公共服务 | AP3、AP5、AP6、AP9、AP10、AP13、AP15 |
| 电商消费品 | AP1、AP2、AP4、AP9、AP10、AP11 |

## 1. 行业通用条目

| 编号 | 条目 | 现象 | 后果 | 改正动作 |
|---|---|---|---|---|
| AP1 | 结构未确认即做视觉 | 信息结构与主流程未定即开始配色与组件样式 | 页面可看不可用，返工从视觉回退到结构 | 先过页面清单 gate，见 `references/product-wireframe-playbook.md` 第 4 节 |
| AP2 | 形容词替代参数 | UI 规格只写「现代」「高级」，无数值与 token 名 | 执行一致性无法保证，评审无判定依据 | 逐条补参数，对照 `references/ui-design-system-guide.md` 第 0 节 |
| AP3 | 五状态缺失 | 页面只有默认态，缺空、错误、加载或权限 | 前端自行发挥，行为不可预期 | 补齐五状态，缺一即标风险（R4） |
| AP4 | 信息层级平铺 | 相同卡片、字号、权重平铺全部区块 | 视线无处落点，主操作被淹没 | 按用户决策顺序排布，层级与优先级对应 |
| AP5 | 语义色混用 | 主色承担多种语义，警示色与错误色混用 | 用户无法预判状态，误判上升 | 按主色、成功、警示、错误、中性五类分派 |
| AP6 | 关键信息低对比 | 辅助文字用弱对比色，浅底配深灰字低于门槛 | 弱视与强光环境读不到（R6） | 按 `references/ui-design-system-guide.md` 第 3.2 节复算达标 |
| AP7 | 主操作错位 | 最突出的按钮不是该页主要任务 | 核心任务完成率下降，页面被绕过 | 先定页面目标再选主操作，视觉权重随目标 |
| AP8 | 操作远离上下文 | 主操作与所需信息分处两端，或需多次跳转 | 路径变长，流程中断 | 操作置于上下文就近处，跨页动作压到一次 |
| AP9 | Chip 与 Tag 溢出 | 标签横向排列无换行规则，窄屏撑出容器 | 窄屏与放大字号下标签不可见 | 补 `flex-wrap: wrap` 或「+3」披露，见 `references/resilient-text.md` T3 |
| AP10 | 伪需求未识别 | 需求以竞品功能罗列为主，说不清受益人 | 功能上线后无人使用 | 按 4 信号逐项检查，见 `references/clarification-gate.md` 第 2.1 节 |
| AP11 | 需求覆盖缺口 | 只有页面与组件，缺需求到章节的对应关系 | 评审阶段才发现漏做，返工成本最高 | 产出需求覆盖矩阵（C10） |
| AP12 | 状态仅靠颜色 | 徽章只用红点或色块表示失败与待处理 | 色觉障碍用户误判状态 | 颜色、图标、文字至少提供两个，见 `resilient-text.md` T4 |
| AP13 | 风格类高危 | 新拟态或毛玻璃承载正文；金融政务用紫粉渐变 | 正文对比度不足，与品类气质冲突 | 正文改纯色底，风格仅用于装饰与叠加层 |
| AP14 | 评审类高危 | 未读页面即判通过；只查样式；把评审级原型写成生产级代码 | 结论不可信，研发按生产级预期排期 | 逐条附证据；按十项检查表过；交接文档写明定位（R1、R2） |

## 2. 风格类高危条目展开

| 编号 | 风格 | 现象 | 后果 | 改正动作 |
|---|---|---|---|---|
| AP13-1 | Neumorphism | 新拟态（同色系浅浮雕）用于卡片正文、表格文字、说明段落 | 同色系下文字与背景对比度极低，通常低于 4.5:1 | 正文区改纯色底加常规文字色，新拟态只用于装饰区块与控件外框 |
| AP13-2 | Glassmorphism | 毛玻璃卡片直接承载正文、表格、输入框 | 背景模糊降低文字对比度，实时模糊带来渲染开销 | 毛玻璃只用于背景图叠加层与导航栏，正文落在不透明底色上 |
| AP13-3 | 行业禁忌色 | 医疗用纯饱和红传达常规状态；政务用深色底；电商首屏无价格与主操作 | 可信度下降，主任务不突出 | 按行业禁忌矩阵逐维度对照，见 `references/industry-style-filter.md` 第 2 节 |

## 3. 评审类高危条目展开

| 编号 | 现象 | 后果 | 改正动作 |
|---|---|---|---|
| AP14-1 | 未实际读取原型文件或未在浏览器打开即给通过结论 | 结论不可信，问题在下一阶段集中暴露（R2） | 逐条附证据位置，无证据只列待核对项 |
| AP14-2 | 只比对视觉，不检查主流程、状态覆盖、响应式与运行时交互 | 视觉合格但不可用，无法支撑开工（R4） | 按 `references/pre-delivery-checklist.md` 十项逐项过 |
| AP14-3 | 交接文档出现「可直接上线」「生产可用」 | 缺工程架构、接口、权限、错误码与测试，排期偏差（R1） | 头部写明评审级定位，缺工程上下文部分列入已知缺口 |

## 4. 判定纪律

| 编号 | 规则 |
|---|---|
| D1 | 判定以现象为准，不凭印象 |
| D2 | 现象描述需可截图或可复现 |
| D3 | 改正动作须能指派给具体角色 |
| D4 | 与检查表 C1 至 C10 结论冲突时，以检查表为准 |

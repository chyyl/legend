# 界面文案规范

本文件供 `experts/03-wireframe-to-ui-expert.md` 与 `experts/05-ui-to-prototype-expert.md` 使用。产出的文案进入 UI 规格的文案列与原型界面。

## 1. 按钮动词化规则

按钮文案用「动词 + 宾语」，说明点击后会发生什么。

| 禁止 | 推荐 | 理由 |
|---|---|---|
| OK | 保存修改 | 未说明后果 |
| 提交 | 创建账号 | 未说明产生什么 |
| 是 | 删除消息 | 确认动作不明确 |
| 取消 | 保留编辑 | 未说明「取消」的实际含义 |
| 点击这里 | 下载 PDF | 未说明目标 |
| 删除 | 移除（仅可恢复时） | 「删除」表示不可逆，「移除」表示可恢复，两者不可混用 |

危险操作按钮必须带数量：「删除 5 项」优于「删除所选」。

## 2. 错误提示三段式

每个错误提示回答三个问题：发生了什么、为什么、怎么修。

| 段 | 要求 | 示例 |
|---|---|---|
| 发生了什么 | 指出具体字段或对象 | 邮箱地址格式不正确 |
| 为什么 | 说明规则或原因 | 需要包含 @ 符号 |
| 怎么修 | 给出可执行动作或正确示例 | 参考：name@example.com |

## 3. 空状态三段式

| 段 | 要求 | 示例 |
|---|---|---|
| 承认现状 | 说明当前无数据 | 还没有项目 |
| 说明价值 | 说明填充后的收益 | 创建项目后可统一管理成员与进度 |
| 给出动作 | 提供一个明确按钮 | 创建第一个项目 |

## 4. 场景禁止与推荐对照

| 场景 | 禁止 | 推荐 | 理由 |
|---|---|---|---|
| 按钮 | 「确定」「提交」「点此」 | 「保存修改」「创建账号」 | 动词加宾语说明后果 |
| 危险操作 | 「删除所选」「确认删除」 | 「删除 5 项，删除后不可恢复」 | 数量与不可逆性必须显式 |
| 格式错误 | 「输入无效」「格式错误」 | 「邮箱需要包含 @ 符号，例如 name@example.com」 | 给出规则与示例 |
| 权限不足 | 「无权限」「403」 | 「你没有访问该项目的权限，可联系项目管理员申请」 | 说明限制与替代动作 |
| 网络错误 | 「网络异常」 | 「未能连接到服务器，请检查网络后重试」 | 说明对象与动作 |
| 服务端错误 | 「服务器错误」「出错了」 | 「服务暂时不可用，可稍后重试或导出本地副本」 | 不暴露错误码，给替代动作 |

服务端错误禁止向用户暴露错误码与堆栈信息。

## 5. Voice 与 Tone

Voice 是品牌语气，全局一致。Tone 随场景调整。

| 场景 | Tone 要求 | 示例 |
|---|---|---|
| 成功 | 简短、确认 | 已保存，修改已生效 |
| 错误 | 先共情后给方案 | 保存未成功，请检查网络后重试 |
| 加载 | 安抚、说明在做什么 | 正在保存草稿 |
| 危险确认 | 严肃、明确后果 | 删除该项目？删除后无法恢复 |

错误场景禁止使用幽默与调侃语气，用户已处于受阻状态。

## 6. 术语一致性

同一概念只用一个词，全界面统一。

| 不一致写法 | 统一写法 |
|---|---|
| 删除 / 移除 /  Trash 混用 | 删除（不可逆场景统一用删除） |
| 设置 / 偏好 / 选项混用 | 设置 |
| 登录 / 登入 / 进入系统混用 | 登录 |
| 新建 / 添加 / 创建混用 | 创建 |

## 7. 无障碍与国际化

| 项 | 规则 |
|---|---|
| 链接文案 | 脱离上下文也能读懂，「查看定价方案」优于「点击这里」 |
| 替代文本 | 描述信息本身，「第四季度营收增长 40%」优于「图表」；装饰性图片用空值 |
| 图标按钮 | 补 `aria-label` |
| 文案膨胀预留 | 按钮与表格列预留空间，德语约加 30%，法语约加 20%，芬兰语约加 30% 至 40% |
| 数字与单位分离 | 「新消息：3」优于「你有 3 条新消息」 |
| 避免缩写 | 「5 分钟前」优于「5 mins ago」 |

## 8. 冗余文案处理

标题已说明的内容不再重复 introductory 段落，按钮已明确的内容不再额外解释。一处信息说一次并说清楚。

## 9. 表单说明

格式用占位符示例表达，不用长句说明。非显而易见的字段需解释为何需要该信息。校验提示放在字段附近，不用弹窗汇总。

# 交付契约

本文件定义技能输出的最低标准。任务不需要完整链路时，只应用相关章节即可。

## 1. 需求到产品结构

必须包含：
- 目标与非目标。
- 目标用户与使用场景。
- 页面清单与每个页面存在的理由。
- 主路径、分支路径、异常路径。
- 空状态、加载状态、错误状态、权限状态。
- 功能模块表。
- 评审风险与待决策事项。

不通过条件：
- 主用户任务无法完成。
- 只列页面，不解释页面为什么存在。
- 把缺失信息当成已确认事实。

## 2. 流程到线框图

必须包含：
- 页面目标。
- 页面区块结构。
- 信息优先级。
- 主要操作与次要操作。
- 交互说明。
- 状态覆盖。
- 入口、出口与跳转关系。

不通过条件：
- 主操作不清楚。
- 关键状态被忽略。
- 页面布局顺序不符合用户决策顺序。

## 3. 线框图到 UI 规格

必须包含：
- 视觉方向及理由。
- 字体层级。
- 颜色使用规则。
- 间距与信息密度。
- 组件视觉规则。
- 状态反馈。
- 可读性与无障碍注意事项。
- 参数建议段（字体、间距 token、断点、主交互时序、触控尺寸）。
- 无障碍门槛（普通文本 >= 4.5:1，关键控件 >= 3:1）。

不通过条件：
- 只说“现代、简洁、高级”等抽象形容词。
- 核心文字在真实预览尺寸下不可读。
- 视觉装饰削弱任务效率。

## 4. UI 到设计系统

必须包含：
- 语义 token 表。
- 核心组件清单。
- 组件状态。
- 组件使用边界。
- 不可复用的一次性元素。
- 必要时补充前端映射说明。
- token 三层映射（原始值/语义/组件）。
- 复用边界判定（可复用、不可复用、待确认）。

不通过条件：
- token 只有原始数值，没有语义用途。
- 组件缺少聚焦、禁用、加载、错误等状态。
- 没有区分可复用规则和页面临时方案。

## 5. UI 到前端交接 / 原型

必须包含：
- 组件拆分。
- 字段与校验表。
- 事件与预期行为。
- 接口与数据假设。
- 埋点建议。
- 响应式规则。
- 原型范围与非生产边界。
- 关键断点下的布局变化表（至少移动端/笔记本/桌面宽屏）。
- 交互时序与失败反馈说明（至少覆盖提交、校验、回退场景）。

不通过条件：
- 交互没有说明目标元素和预期结果。
- 没有工程上下文却声称已达到生产可用。

## 6. 原型评审

必须包含：
- 评审结论：通过、带风险通过、不通过。
- P0 / P1 / P2 问题清单。
- 证据位置。
- 影响说明。
- 修复建议。
- 已知缺口。
- 设计质量评分（100 分制）及主要扣分依据。

不通过条件：
- 没有实际读取文件或页面却声称通过。
- 只检查视觉，不检查流程、状态、响应式与运行时交互。

# 产品与线框图操作手册

## 1. 先确认任务，而不是先画页面

开始设计前，先回答：
- 用户是谁？
- 用户要完成什么任务？
- 任务成功的判断标准是什么？
- 哪些内容是本次不做的？
- 哪些信息缺失会影响关键决策？

## 2. 页面清单的判断方法

每个页面都必须对应一个明确任务。常见页面类型：
- 列表页：帮助用户筛选、比较、进入详情。
- 详情页：帮助用户理解单个对象并采取行动。
- 编辑页：帮助用户创建或修改对象。
- 配置页：帮助用户设置规则。
- 结果页：告诉用户操作是否成功以及下一步做什么。

## 2.1 布局决策矩阵（新增）

在进入 UI 之前，先做布局选择：

| 场景 | 优先布局 | 适用原因 | 常见误用 |
|---|---|---|---|
| 数据密集后台 | 左侧导航 + 主内容区 + 表格/面板 | 易于多任务切换与筛选 | 首页堆满卡片，导致核心任务不可见 |
| 内容浏览/营销 | 分段式纵向布局 | 强调叙事和转化路径 | 过多并列信息导致阅读断裂 |
| 流程型任务 | 步骤式布局（步骤条 + 表单/选择） | 用户知道当前进度与下一步 | 把所有步骤放同屏，认知负担过高 |
| 移动端高频操作 | 单列 + 大点击区 + 底部主操作 | 适配拇指区域和小屏信息密度 | 延用桌面双栏导致拥挤和误触 |

选择布局时至少回答：
- 主任务是什么，首屏是否可见。
- 用户第一眼先看哪里，第二步做什么。
- 关键操作是否离任务上下文足够近。
- 异常、空、加载、权限状态放在哪个区块展示。

## 3. 信息架构五层

每层回答一个独立问题，逐层确认后再进入下一层。上层未确认不进入下层。

| 层 | 定义 | 关键问题 | 输出 |
|---|---|---|---|
| 导航结构 | 用户如何在页面之间移动 | 一级入口有哪些；从任意页面能否 2 次点击内到达主任务 | 站点地图或页面树 |
| 内容层级 | 页面内信息如何分组 | 每屏能否说清主次；主操作是否唯一突出 | 区块结构与顺序 |
| 命名规范 | 页面、按钮、字段、状态怎么称呼 | 同一概念是否只有一个名称 | 术语表 |
| 核心实体 | 系统操作的对象有哪些 | 有哪些名词；每个实体有哪些属性与状态 | 实体清单 |
| 实体关系 | 实体之间如何关联 | 一对一、一对多、多对多分别是什么；从哪个实体可跳到哪个 | 关系表 |

落地要求：五层的输出进入 `references/structured-artifacts.md` 第 2 节页面清单的对应字段，命名规范同时用于 `references/ux-writing-rules.md` 第 6 节术语统一。

## 4. 页面清单 gate

进入线框设计前逐条检查，五项全部通过才放行。

| 编号 | 检查项 | 通过条件 |
|---|---|---|
| G1 页面有目标 | 每页能写出一句话目标 | 目标句包含用户与要完成的事 |
| G2 页面有存在理由 | 能说明为什么不合并到相邻页 | 存在理由为具体差异，非「习惯如此」 |
| G3 有主操作 | 每页能确定一个主操作 | 主操作与该页目标一致 |
| G4 状态覆盖 | 每页覆盖状态数不少于 4 项 | 含主状态、空、错误、加载、权限中的至少 4 项 |
| G5 跳转关系完整 | 入口与出口闭合 | 每页有明确来源与去向，孤立页为零 |

不通过时的降级处理：

| 不通过项 | 降级动作 |
|---|---|
| G1 或 G3 不通过 | 该页不进入本轮范围，移入待确认事项，补问后再定 |
| G2 不通过 | 合并到相邻页面，页面数减少 |
| G4 不通过 | 保留页面但标风险，线框阶段只画已覆盖状态，缺项在页面清单注明 |
| G5 不通过 | 补入口或补出口，两项都无法确定时该页暂缓 |

降级不改变红线 R4 的五状态要求：降级只影响本轮范围，须在产物中显式记录被降级项与原因。

## 5. 线框图必须覆盖的状态

至少覆盖：
- 默认状态。
- 空状态。
- 加载状态。
- 错误状态。
- 权限不足状态。
- 部分成功或冲突状态。

## 6. 信息优先级

页面信息应按用户决策顺序排列：
1. 先看当前对象是什么。
2. 再看是否需要处理。
3. 再看处理依据。
4. 最后执行主要操作。

补充规则：
- 主操作在视觉上应唯一突出，不与次操作等权。
- 风险操作应与主操作区分，避免误触。
- 表格场景下，操作列尽量靠近主要识别字段，减少视线往返。

## 7. 评审时常见问题

- 页面很多，但用户任务没有闭环。
- 表格字段太多，却没有说明字段用途。
- 只画理想状态，没有异常状态。
- 主按钮与用户最重要的动作不一致。

# 错误码（E 码）

本文件定义技能包在输入缺失、阻断与降级场景下使用的错误码。`experts/` 下六份专家文件、`workflows/` 下六份流程文件、`qa/delivery-checklist.md`、`playbooks/expert-router.md` 与 `data/` 的结构化字段均按本表的码值登记。

**登记规则**：任一必需输入字段缺失时，不得继续主交付，须在交付物中写明 E 码、缺失字段、已交付部分与恢复条件。只写「信息不足」而不给 E 码，视为交付不合规。

## 0. 使用规则

| 编号 | 规则 |
|---|---|
| R1 | 命中阻断条件时必须登记 E 码，不允许只写「信息不足」 |
| R2 | E 码写入 `openQuestions[].errorCode` 字段，阻断类问题的 `blocking` 为 true |
| R3 | 登记 E 码不等于停止工作，必须同时给出降级交付内容与恢复条件 |
| R4 | 页面文案与界面提示不得暴露 E 码，E 码只出现在评审与交接材料中 |
| R5 | 同一缺失项在一次任务中只登记一次，不重复计数 |
| R6 | 补齐缺失项后重新判定，命中恢复条件即移出阻断清单 |

## 1. 码值总览

| E 码 | 名称 | 级别 | 触发条件 | 恢复条件 |
|---|---|---|---|---|
| E-INPUT-01 | 原始需求缺失 | 阻断 | `userInput` 缺失 | 取得原始需求文本 |
| E-INPUT-02 | 交付形态未确认 | 阻断 | `outputPurpose` 缺失 | 确认评审、开发交接或演示 |
| E-INPUT-03 | 目标用户未确认 | 阻断 | `targetUsers` 缺失 | 明确至少一类用户角色 |
| E-INPUT-04 | 截图不可读 | 阻断 | `screenshots` 存在但不可读 | 取得可读截图或页面文字说明 |
| E-INPUT-05 | 页面清单缺失 | 阻断 | `pages` 缺失，需先执行 01 段 | 产出页面清单 |
| E-INPUT-06 | 主路径缺失 | 阻断 | `mainPath` 缺失，页面顺序无法确定 | 产出可复述的主路径 |
| E-INPUT-07 | 线框规格缺失 | 阻断 | `wireframeSpec` 缺失 | 取得线框规格或页面说明 |
| E-INPUT-08 | 主操作未指定 | 阻断 | `primaryActions` 缺失或不唯一 | 每页确定恰好 1 个主操作 |
| E-INPUT-09 | UI 页面数不足 | 阻断 | `uiPages` 缺失或少于 2 页 | 取得不少于 2 页 UI 输出 |
| E-INPUT-10 | UI 规格缺失 | 阻断 | `uiSpec` 缺失，需先执行 03 段 | 取得 UI 规格 |
| E-INPUT-11 | 原型证据不可读 | 阻断 | `prototypeFile` 未成功读取 | 提供可读原型文件 |

## 2. 各级别的交付要求

| 级别 | 含义 | 允许交付的内容 |
|---|---|---|
| 阻断 | 不得进入本阶段 | 缺口清单、降级说明、已确认事实、待补问题、恢复条件 |
| 降级 | 可交付但不完整 | 草稿级产物，且必须在首行标注降级状态与 E 码 |

## 2.1 降级缺省约定

以下字段缺失不阻断，按缺省值推进但须标注。标注位置与该字段的处理方式一致。

| 字段 | 缺省处理 | 标注要求 |
|---|---|---|
| `businessGoal` | 追问一次，仍缺失则标为假设 | 标为假设并阻断进入 02 |
| `prd` | 带假设推进 | 标注影响范围 |
| `existingPages` | 按全新设计处理 | 标注按全新设计 |
| `industryContext` | 缺省不做行业声明 | 03 阶段需重问 |
| `constraints` | 列入待确认事项 | 写入待确认 |
| `businessRules` | 列入 `openQuestions` | 标 `blocking` |
| `blocks` | 由本段按用户任务推导 | 标注为假设 |
| `wireframeSource` | 按 `blocks` 推导 | 标注来源为推导 |
| `brandAssets` | 用中性色系 | 标注可替换 |
| `density` | 按标准 | 标注缺省值 |
| `fontScale` | 按 5 级补齐 | 标注默认值 |
| `colorSemantics` | 从页面取色 | 标注待确认 |
| `components` | 由页面区块归纳 | 标注需人工确认 |
| `uiSpec`（04 段） | 从页面反推 token | 标注来源为反推 |
| `designTokens` | 用原始值 | 标注待语义化 |
| `frontendTarget` | 按 CSS 变量给映射建议 | 标注缺省 |
| `apiContext` | `apiAssumptions` 全部标 `confirmed` 为 false | 标注未确认 |
| `analyticsNeeds` | 埋点按主操作推导 | 标注为推导 |
| `targetDevices` | 按断点缺省档给出 | 标注缺省档 |
| `accessibilityTarget` | 按 WCAG AA | 标注缺省 |
| `reviewScope` | 按全量 | 标注缺省 |
| `requirementDoc` | 不出需求覆盖矩阵 | 结论中列为无法验证 |
| `uiSpec`（06 段） | 不做设计意图比对 | `uncovered` 中登记 |
| `releaseTarget` | 不阻断 | 影响是否追加发布门禁检查 |

带假设推进的字段，其假设须写入 `assumptions` 数组，每条含 `source` 与 `impact`。

## 3. 逐码详表

### E-INPUT-01 原始需求缺失

| 项 | 内容 |
|---|---|
| 触发 | `userInput` 缺失 |
| 级别 | 阻断，无缺省值 |
| 判定 | 取得一段可复述的原始需求文本 |
| 允许交付 | 追问清单、已知信息、需用户补充的最小信息集 |
| 禁止 | 用推测填充需求后继续主线 |
| 恢复条件 | 取得原始需求文本 |
| 关联 | `references/clarification-gate.md` 的 G1 门禁 |

### E-INPUT-02 交付形态未确认

| 项 | 内容 |
|---|---|
| 触发 | `outputPurpose` 缺失 |
| 级别 | 阻断，缺省按「评审」处理并标注 |
| 判定 | 明确评审、开发交接或演示三选一 |
| 允许交付 | 按评审口径的降级产物，标注交付形态待确认 |
| 禁止 | 静默按评审处理而不标注 |
| 恢复条件 | 用户确认交付物类型 |

### E-INPUT-03 目标用户未确认

| 项 | 内容 |
|---|---|
| 触发 | `targetUsers` 缺失 |
| 级别 | 阻断，缺省按待确认角色占位并列入追问 |
| 判定 | 能用一句话说清为谁解决什么问题 |
| 允许交付 | 用户角色占位表、角色维度追问清单、假设及其影响面 |
| 禁止 | 把占位角色当作已确认事实 |
| 恢复条件 | 明确至少一类用户角色 |
| 关联 | `references/clarification-gate.md` 的 G1 门禁 |

### E-INPUT-04 截图不可读

| 项 | 内容 |
|---|---|
| 触发 | `screenshots` 存在但不可读，且未提供页面文字说明 |
| 级别 | 阻断 |
| 判定 | 取得可读截图或页面文字说明 |
| 允许交付 | 待补材料清单、需用户补充的页面说明项 |
| 禁止 | 凭截图标题猜测页面内容 |
| 恢复条件 | 取得可读截图或页面文字说明 |

### E-INPUT-05 页面清单缺失

| 项 | 内容 |
|---|---|
| 触发 | `pages` 缺失，需先执行 01 段 |
| 级别 | 阻断 |
| 判定 | 每页有目标、有存在理由、有主操作、状态覆盖不少于 4 项、跳转关系完整 |
| 允许交付 | 信息架构缺口清单、待确认页面候选及各自存在理由 |
| 禁止 | 直接进入区块布局；页面清单未定前画线框 |
| 恢复条件 | 页面清单通过 gate |
| 关联 | `references/product-wireframe-playbook.md` 第 4 节页面清单 gate |

### E-INPUT-06 主路径缺失

| 项 | 内容 |
|---|---|
| 触发 | `mainPath` 缺失，页面顺序无法确定 |
| 级别 | 阻断 |
| 判定 | 主路径至少 2 步且可被独立复述 |
| 允许交付 | 主路径候选序列、每步的入口与出口说明 |
| 禁止 | 在主路径未定时自行排列页面顺序并当作已确认 |
| 恢复条件 | 产出可复述的主路径 |

### E-INPUT-07 线框规格缺失

| 项 | 内容 |
|---|---|
| 触发 | `wireframeSpec` 缺失 |
| 级别 | 阻断，需先执行 02 段或提供页面说明 |
| 判定 | 线框规格含区块结构与信息优先级 |
| 允许交付 | 需补齐项清单、已确定的视觉方向草稿 |
| 禁止 | 在信息架构未定时先做视觉包装 |
| 恢复条件 | 取得线框规格 |

### E-INPUT-08 主操作未指定

| 项 | 内容 |
|---|---|
| 触发 | `primaryActions` 缺失，或某页主操作不唯一 |
| 级别 | 阻断，视觉焦点与事件表均无法定义 |
| 判定 | 每页恰好一个主操作 |
| 允许交付 | 页面目标、候选主操作 2 至 3 套、各自的取舍理由、待用户选择项 |
| 禁止 | 输出一套方案并声称确定；在同页并列多个同等权重主按钮 |
| 恢复条件 | 用户选定主操作 |
| 关联 | `references/product-wireframe-playbook.md` 第 7 节评审常见问题 |

### E-INPUT-09 UI 页面数不足

| 项 | 内容 |
|---|---|
| 触发 | `uiPages` 缺失或少于 2 页 |
| 级别 | 阻断，少于 2 页不构成系统 |
| 判定 | 不少于 2 页真实 UI 输出 |
| 允许交付 | 「页面数不足」说明与单页 token 草稿，标注为临时版本 |
| 禁止 | 凭空构造 token 冒充既有系统；把草稿称为设计系统 |
| 恢复条件 | 补充真实页面至 2 页以上 |
| 关联 | `workflows/design-system-extract.md` 的 S1 门禁 |

### E-INPUT-10 UI 规格缺失

| 项 | 内容 |
|---|---|
| 触发 | `uiSpec` 缺失，需先执行 03 段 |
| 级别 | 阻断 |
| 判定 | UI 规格含字体层级、颜色语义、间距 token 与断点 |
| 允许交付 | 需补齐项清单、可从页面反推的部分标注来源为反推 |
| 禁止 | 在无 UI 规格时输出事件表与交接清单 |
| 恢复条件 | 取得 UI 规格 |
| 关联 | `references/ui-design-system-guide.md` 第 0 节参数化最小规范 |

### E-INPUT-11 原型证据不可读

| 项 | 内容 |
|---|---|
| 触发 | `prototypeFile` 未成功读取，或读取后无法标注证据位置 |
| 级别 | 阻断 |
| 判定 | 文件可读，且每条问题能指向文件与行号或区块名 |
| 允许交付 | 待验证项清单、每个待验证项的验证方式、需用户补充的材料 |
| 禁止 | 输出「通过」或「带风险通过」；声称已完成评审但列不出证据位置 |
| 恢复条件 | 提供可读文件 |
| 关联 | `qa/delivery-checklist.md` 的 P0 阻断项、`references/pre-delivery-checklist.md` |

## 4. 按阶段索引

| 阶段 | 相关 E 码 | 阻断后果 |
|---|---|---|
| 01 需求到产品结构 | E-INPUT-01、02、03、04 | 停止主交付，只输出追问与降级说明 |
| 02 流程到线框图 | E-INPUT-05、06、03 | 停止区块级输出，只交付信息架构缺口清单 |
| 03 线框到 UI 规格 | E-INPUT-07、05、08 | 不输出视觉规则，只交付需补齐项 |
| 04 UI 到设计系统 | E-INPUT-09 | 停止系统化输出，交付页面数不足说明与单页 token 草稿 |
| 05 UI 到前端交接 | E-INPUT-10、05、08 | 不输出事件表与交接清单，只交付缺口 |
| 06 原型评审 | E-INPUT-11 | 禁止输出通过或带风险通过，只输出无法验证与降级说明 |

## 5. 跨阶段复用码

以下字段在多个阶段复用，登记时须写明阶段。

| E 码 | 字段 | 各阶段差异 |
|---|---|---|
| E-INPUT-03 | `targetUsers` | 01 段与 02 段均缺省为待确认角色占位 |
| E-INPUT-05 | `pages` | 02 段需先执行 01；03 段与 05 段缺省停止输出并回退到 02 |
| E-INPUT-08 | `primaryActions` | 03 段缺省则视觉焦点无法确定；05 段缺省则事件表无法定义 |

## 6. 交付中的登记格式

`data/schemas/page-inventory.schema.json` 中 `openQuestions[]` 的结构：

| 字段 | 类型 | 说明 |
|---|---|---|
| `question` | 字符串 | 缺失项的追问句，长度不小于 4 |
| `blocking` | 布尔 | 为 true 时阻断进入下一阶段 |
| `errorCode` | 字符串 | 阻断类问题填 E 码 |

登记示例：

| 字段 | 示例 |
|---|---|
| E 码 | E-INPUT-06 |
| 缺失字段 | `mainPath` |
| 影响面 | 02 段区块布局无法开始；03 至 06 段连带阻断 |
| 已交付部分 | 主路径候选序列及每步入口与出口 |
| 恢复条件 | 主路径至少 2 步且可被独立复述 |
| 待补问题 | 3 条，选项化 |

## 7. 与 P0 判定的关系

按 `qa/delivery-checklist.md`，出现以下任一情况判不通过：

| 情形 | 相关 E 码 |
|---|---|
| 必需输入字段缺失仍继续主交付，且未登记 E 码 | 全部 11 项 |
| 未读取目标文件却声称完成评审 | E-INPUT-11 |
| 原型主路径无法完成 | E-INPUT-06、E-INPUT-08 |

E 码登记本身不构成 P0。未登记才是 P0；已登记并给出降级交付说明的，不判不通过。

## 8. 界面侧错误文案

E 码供内部评审与交接使用。用户可见文案按 `references/ux-writing-rules.md` 的三段式表达：发生了什么、为什么、怎么修。

| 场景 | 是否用 E 码 | 文案要求 |
|---|---|---|
| 表单格式错误 | 否，属字段级校验 | 说明规则并给示例 |
| 权限不足 | 否，属权限态 | 说明限制与替代动作 |
| 服务端错误 | 否，属异常态 | 给替代动作，不暴露错误码与堆栈 |
| 输入缺失阻断 | 是，转为内部登记项 | 不在界面展示 E 码 |

## 9. 边界

本表覆盖阻断与降级两类可判定情形。判断本身的技术质量由 `qa/delivery-checklist.md` 的 P0 至 P3 分级负责，两者不重复：一个说「能不能往下走」，一个说「做得够不够好」。本表只覆盖输入侧缺失导致的阻断，不覆盖设计质量判定，也不覆盖需求侧澄清门禁（见 `references/clarification-gate.md` 的 MRC 门禁）。
